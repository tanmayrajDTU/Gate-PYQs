Regular Expressions & Finite Automata

DFA · NFA · ε-NFA · SUBSET CONSTRUCTION · MINIMIZATION · REGEX ↔ FA EQUIVALENCE

DFA — the formal definition

A deterministic finite automaton is a 5-tuple (Q, Σ, δ, q₀, F): a finite set of states Q, an input alphabet Σ, a total transition function δ: Q×Σ→Q, a start state q₀, and a set of accepting states F. "Deterministic" means exactly one transition per (state, symbol) pair — no missing transitions, no choices.

DFA accepting all strings over {a,b} ending in "ab" — q2 is the only accepting (double-circled) state

NFA and the subset construction (NFA → DFA)

An NFA relaxes δ to allow zero, one, or multiple transitions per (state, symbol) pair, plus optional ε-transitions (moves that consume no input). Every NFA has an equivalent DFA — this is a core GATE result, not just intuition. The standard construction:

  1. Each DFA state = a set of NFA states (a subset of Q).
  2. Start state of the DFA = ε-closure of the NFA's start state.
  3. For each DFA state S and symbol a: new state = ε-closure(⋃ over q∈S of δ(q,a)).
  4. A DFA state is accepting if it contains at least one NFA accepting state.
GATE trap

Subset construction can produce up to 2ⁿ DFA states for an n-state NFA in the worst case — GATE frequently asks for the minimum number of states in the resulting DFA, which requires actually building the reachable subsets (unreachable subsets don't count) rather than assuming the full 2ⁿ blow-up.

Minimization — merging equivalent states

Two states are equivalent (mergeable) if, for every possible input string, they either both lead to acceptance or both lead to rejection. These are related but distinct ideas: the Myhill–Nerode theorem is the theoretical characterization — it defines an equivalence relation on strings and proves that a regular language has a unique minimal DFA whose states correspond exactly to the equivalence classes of that relation. The table-filling algorithm is the concrete procedure used to actually compute state-equivalence on a given DFA: it starts by marking accepting vs. non-accepting states as distinguishable, then iteratively marks any pair whose transitions lead to an already-distinguished pair, until no new pairs are marked. In short — Myhill–Nerode tells you a minimal DFA exists and is unique; table-filling is how you find it.

Regular expressions ↔ finite automata

Kleene's theorem: a language is regular if and only if some finite automaton accepts it if and only if some regular expression describes it. All three views are interchangeable, and GATE tests conversions in every direction.

GATE trap — four related-but-different representations, don't conflate the terms

The standard construction path is: regular expression → ε-NFA (Thompson's construction, the natural way to build an NFA from regex operators like union and concatenation, since splicing two machines together is cleanest via ε-links) → NFA (eliminate ε-transitions via ε-closure, if a strict ε-free NFA is needed as an intermediate step) → DFA (subset construction). All four represent the exact same class of languages (regular languages) — the differences are purely about how nondeterminism and empty moves are permitted in the machine, not about expressive power. When a GATE question mixes "NFA" and "ε-NFA" terminology loosely, check whether ε-transitions are actually present in the diagram/definition given — that determines which construction step applies, regardless of which label the question uses.

ε vs ∅ — don't confuse these

ε denotes the empty string (a string of length 0, which is itself a valid match) — the language {ε} is nonempty, it contains exactly one string. ∅ denotes the empty language (a set with no strings at all, not even ε). L·∅ = ∅ for any L, but L·{ε} = L.

Practice — GATE style (original)

5 questions
Q1 How many states does the minimal DFA need to accept all binary strings divisible by 3 (treating the string as a binary number)?

Track the remainder mod 3 as you read bits left to right: state transitions are r → 2r mod 3 on '0' and r → (2r+1) mod 3 on '1'. There are exactly 3 possible remainders (0,1,2), each needing its own state, and none can be merged since they behave differently on future input.

Answer: 3 states

Q2 An NFA has 4 states. What is the maximum number of states in the DFA produced by subset construction, before minimization?

Subset construction can produce up to 2ⁿ states for an n-state NFA in the worst case (one DFA state per possible subset of NFA states, including the empty "dead" subset). This bound is on the DFA subset construction directly outputs — it is not a bound on the minimal DFA equivalent to the NFA, which can (and typically does) have fewer states after minimization.

Answer: 2⁴ = 16 states (worst case, before minimization)

Q3 Is the regular expression (a∪b)* equal to the regular expression a*b*(a∪b)*? Justify briefly.

(a∪b)* already generates every possible string over {a,b}, since it can produce any sequence of a's and b's in any order and any count including zero. Prepending a*b* doesn't add any string that wasn't already generated by (a∪b)* alone — both describe the same language, Σ*.

Answer: Yes, both describe Σ* (all strings over {a,b})

Q4 During DFA minimization by the table-filling method, two states p and q are both non-accepting, and on every input symbol they transition to the same next state. Are p and q distinguishable?

They start in the same class (both non-accepting), and every transition from p and q leads to an identical next state — so no future input can ever tell them apart. They are equivalent and should be merged.

Answer: No, they are equivalent (mergeable)

Q5 Convert the regular expression (ab)* into a description of the language it generates.

(ab)* means the block "ab" repeated zero or more times: ε, ab, abab, ababab, and so on — never a lone 'a' or lone 'b' without its pair.

Answer: {ε, ab, abab, ababab, ...} — even-length strings alternating a,b starting with a

Regular Languages, Closure & Pumping Lemma

CLOSURE PROPERTIES · PUMPING LEMMA (REGULAR) · DECISION PROPERTIES

Closure properties of regular languages

Regular languages are closed under: union, intersection, concatenation, Kleene star, complementation, and reversal — meaning applying any of these operations to regular language(s) always produces another regular language. This closure is exactly why you can build a DFA for a complex condition by combining simpler DFAs (product construction for intersection/union; for complement, first make the DFA complete by adding a sink state for any missing transitions, then swap accept/non-accept states — swapping alone only works if the DFA was already complete).

Product construction (for intersection or union)
Given DFA₁=(Q1,Σ,δ1,q1,F1) and DFA₂=(Q2,Σ,δ2,q2,F2): New states = Q1 × Q2 (pairs) δ((p,q), a) = (δ1(p,a), δ2(q,a)) Intersection: accept if BOTH components are accepting Union: accept if EITHER component is accepting

The Pumping Lemma for regular languages

If L is regular, there exists a pumping length p such that every string w∈L with |w|≥p can be split as w = xyz where:

  • |xy| ≤ p (the pumped part occurs within the first p characters)
  • |y| ≥ 1 (something is actually being pumped)
  • xyⁱz ∈ L for all i ≥ 0 (pumping y any number of times, including zero, keeps the string in L)

Used almost exclusively as a proof-by-contradiction tool to show a language is NOT regular: assume L is regular, take the pumping length p, choose a specific string w∈L with |w|≥p, show that every valid split x,y,z fails the pumping condition for some i, and conclude L can't be regular.

Classic non-regular proof: L = {aⁿbⁿ : n ≥ 0}
Assume L is regular with pumping length p. Choose w = a^p b^p (length 2p ≥ p, so pumping lemma applies) Since |xy| ≤ p, xy consists entirely of a's. So y = a^k for some k ≥ 1. Pump with i=2: xy²z = a^(p+k) b^p — now #a's ≠ #b's. This string is NOT in L, contradicting the pumping lemma. ∴ L is not regular.
GATE trap

The pumping lemma gives a necessary condition for regularity, not a sufficient one — a language can satisfy the pumping lemma's conditions and still fail to be regular (rare "pumping-lemma-proof" languages exist). GATE never asks you to prove a language IS regular using the pumping lemma; it's a one-directional tool for disproving regularity only.

Practice — GATE style (original)

5 questions
Q1 Is L = {aⁿbᵐ : n,m ≥ 0} (any number of a's followed by any number of b's) regular?

Yes — this is exactly the language of the regular expression a*b*, so it's regular by definition (no pumping lemma needed to prove regularity — you just exhibit the regex or DFA).

Answer: Yes, regular (regex: a*b*)

Q2 Is L = {ww : w ∈ {a,b}*} (strings that are some string repeated twice) regular?

Assume L is regular and let p be its pumping length. Choose s = a^p b a^p b, which belongs to L because s = (a^p b)(a^p b). For any decomposition s = xyz with |xy| ≤ p and |y| > 0, y consists only of a's from the first block, say y = a^k where k ≥ 1. Pumping changes only the first block of a's. For an appropriate pumping value (i = 0 or i = 2), the resulting string no longer consists of two identical halves, contradicting the pumping lemma. Therefore L is not regular.

Answer: No, L is not regular.

Q3 Regular languages L1 and L2 are given. Is L1 ∩ L2 guaranteed to be regular?

Yes — regular languages are closed under intersection (via the product construction combining DFAs for L1 and L2), so the intersection of any two regular languages is always regular.

Answer: Yes, always regular

Q4 Is the complement of a regular language always regular?

Yes — but the standard construction needs one careful step first. Given a DFA for L, you can only get a DFA for the complement by swapping accepting and non-accepting states IF the DFA is complete (has a defined transition for every symbol from every state). If the DFA is partial (some state is missing a transition for some input symbol), you must first make it complete — add one new "sink"/"dead" state, and redirect every missing transition to it (with the sink looping to itself on all symbols) — before swapping accept/non-accept. Skipping this step on a partial DFA gives a wrong construction: strings that would have been "rejected" by falling off an undefined transition need to become accepting in the complement, but there's no state for them to land on and accept from until the sink state is added. (Note: this trick specifically requires a DFA, not an NFA, since NFAs don't complement this simply.)

Answer: Yes, always regular — construction: first make the DFA complete (add a sink state for any missing transitions), THEN swap accepting/non-accepting states

Q5 Can the pumping lemma be used to PROVE that a language is regular?

No — the pumping lemma states a necessary condition that all regular languages satisfy, but satisfying it doesn't guarantee regularity. It can only be used to disprove regularity, by showing a language fails the condition.

Answer: No — it's a one-way tool, used only to disprove regularity

03

Context-Free Grammars

CFG DEFINITION · DERIVATIONS & PARSE TREES · AMBIGUITY · CHOMSKY & GREIBACH NORMAL FORMS

CFG — the formal definition

A context-free grammar is a 4-tuple (V, Σ, R, S): a set of variables/non-terminals V, a set of terminals Σ, a set of production rules R of the form A → α (A is a single non-terminal, α is any string of terminals/non-terminals), and a start symbol S. "Context-free" means the left side of every rule is a single non-terminal — no surrounding context is checked before applying a rule.

Classic CFG: balanced parentheses
S → ( S ) S | ε // Derives: ε, (), ()(), (()), (())(), ... // Every derivation keeps parentheses balanced by construction

Leftmost/rightmost derivation & parse trees

A leftmost derivation always expands the leftmost non-terminal first; a rightmost derivation always expands the rightmost one. Both can produce the same final string via different rule-application orders, but each string has (in an unambiguous grammar) exactly one parse tree — the derivation order is just a different traversal of that same tree.

Ambiguity

A grammar is ambiguous if some string in its language has two or more distinct parse trees (not just two derivation orders of the same tree). Ambiguity is a property of the grammar, not the language — the same language can often be described by both an ambiguous and an unambiguous grammar.

GATE trap

The classic example: E → E+E | E*E | id is ambiguous — the string id+id*id has two different parse trees depending on whether + or * is grouped first, since the grammar encodes no precedence. Fixing this requires a layered grammar (E→E+T|T, T→T*F|F, F→id) that bakes precedence into the rule structure itself. GATE frequently asks you to identify ambiguity by finding two distinct parse trees for one specific string, not just eyeball the rules.

Chomsky Normal Form (CNF) & Greibach Normal Form (GNF)

Normal formEvery rule looks likeUse
CNFA → BC or A → a (plus S→ε if ε∈L)Enables CYK parsing algorithm; parse trees are binary
GNFA → aα (a terminal, then zero or more non-terminals)Every derivation step consumes exactly one input symbol

Every context-free language (except possibly needing an explicit S→ε for ε) can be converted to an equivalent CNF or GNF grammar — the conversion process (eliminating ε-productions, unit productions, then restructuring) is a standard multi-step GATE question.

CNF derivation length shortcut

For a CNF grammar (no ε-productions), a parse tree deriving a string of length n uses exactly 2n−1 production applications — n−1 applications of A→BC rules to build the binary tree structure (each one adds one non-terminal, net) plus n applications of A→a rules to replace each of the n leaves with a terminal. Be precise about what's being counted here: "derivation steps" is ambiguous by itself — it could mean production applications (what this 2n−1 count refers to), sentential-form transitions in a specific derivation order (same number, since each production application corresponds to exactly one sentential-form transition in a leftmost or rightmost derivation), or informally "parse-tree expansion operations" (also the same count, for a CNF tree). The formula 2n−1 is correct under all of these readings for CNF specifically, but state which one you mean when the question is ambiguous.

Practice — GATE style (original)

5 questions
Q1 Give a CFG for L = {aⁿbⁿ : n ≥ 0}.

Each 'a' must be matched by a corresponding 'b' on the outside — a self-embedding rule handles this naturally: S→aSb wraps one more a...b pair around a smaller instance, with S→ε as the base case.

Answer: S → aSb | ε

Q2 Is the grammar S → aS | Sa | a ambiguous? Check the string "aaa".

Yes. Deriving "aaa" by always expanding via S → aS gives a right-branching tree; always expanding via S → Sa gives a left-branching tree. These are two genuinely different tree shapes for the same string — not just two orders of writing down the same tree:

Tree 1 (via S → aS, right-branching): Tree 2 (via S → Sa, left-branching): S S / \ / \ a S S a / \ / \ a S S a | | a a

In Tree 1, every S expands as (terminal a) followed by (S) — recursion nests to the right, so the tree leans right. In Tree 2, every S expands as (S) followed by (terminal a) — recursion nests to the left, so the tree leans left. Both trees have "aaa" as their yield (read the leaves left to right), but they are structurally distinct trees — which is exactly what "ambiguous" means: more than one parse tree for the same string, not merely more than one derivation order of one tree.

Answer: Yes, ambiguous — "aaa" has (at least) these two distinct parse trees

Q3 How many production applications are used in a CNF parse tree deriving a string of length 6?

Using the CNF derivation-length formula 2n−1 with n=6: 2×6−1 = 11.

Answer: 11 production applications

Q4 Which of these are NOT in Chomsky Normal Form (select all that apply): (a) A → BC (b) A → a (c) A → aB (d) A → BCD?

CNF only allows A→BC (exactly two non-terminals) or A→a (exactly one terminal). Option (c) mixes a terminal with a non-terminal on the right side (not CNF form, though it is valid GNF form), and (d) has three non-terminals (too many for CNF).

Answer: (c) and (d) are not CNF

Q5 Does every context-free language have an unambiguous grammar?

No — some context-free languages are "inherently ambiguous," meaning every possible grammar for that language is ambiguous. This is a distinct, stronger claim than just "this particular grammar is ambiguous."

Answer: No — some CFLs are inherently ambiguous

Pushdown Automata & CFL Properties

PDA DEFINITION · CFG ↔ PDA EQUIVALENCE · DPDA VS NPDA · PUMPING LEMMA (CFL) · CLOSURE PROPERTIES

PDA — a finite automaton plus a stack

A pushdown automaton extends an NFA with an unbounded stack, giving it exactly enough extra memory to handle nested/matching structure (like balanced parentheses) that finite automata can't track. Transitions can read an input symbol (or ε), pop a stack symbol, and push a string of stack symbols — all in one move.

Fundamental equivalence result

A language is context-free if and only if some PDA accepts it. Every CFG can be mechanically converted into an equivalent PDA (and vice versa) — this equivalence is exactly parallel to the regex↔DFA equivalence one level down the Chomsky hierarchy.

Two acceptance modes — and why they matter

ModeAccepts when...
Final stateInput is fully consumed AND the PDA is in an accepting state (stack contents irrelevant)
Empty stackInput is fully consumed AND the stack is completely empty (accepting states irrelevant)

These two modes are provably equivalent in expressive power — any PDA using one mode can be converted to an equivalent PDA using the other — but a given PDA's specific behavior depends on which mode it's defined to use.

Deterministic PDA (DPDA) vs. nondeterministic PDA (NPDA) — NOT equally powerful

GATE trap — the single most important PDA fact

Unlike finite automata (where NFA = DFA in power), DPDAs are strictly weaker than NPDAs. Deterministic context-free languages (DCFLs) are a proper subset of context-free languages. The classic example: L = {wwᴿ : w∈{a,b}*} (even-length palindromes) is context-free (accepted by an NPDA that nondeterministically "guesses" the midpoint) but has no DPDA — a deterministic machine can never be sure it has found the exact middle of the string without lookahead it isn't given.

The Pumping Lemma for context-free languages

If L is context-free, there's a pumping length p such that every string w∈L with |w|≥p can be split as w = uvxyz where:

  • |vxy| ≤ p (the pumped region is bounded)
  • |vy| ≥ 1 (at least one of v, y is nonempty — something is pumped)
  • uvⁱxyⁱz ∈ L for all i ≥ 0 (v and y are pumped together, the SAME number of times)

Same proof-by-contradiction usage as the regular pumping lemma, but with two pumped pieces (v and y) instead of one — used to show a language is not even context-free.

Classic non-CFL proof: L = {aⁿbⁿcⁿ : n ≥ 0}
Choose w = a^p b^p c^p. Any window vxy of length ≤ p can span at most 2 of the 3 letter-blocks (a's, b's, c's). Pumping v and y (i=2) increases the count of at most 2 letters, breaking the a=b=c equality. ∴ L is not context-free.

Closure properties of context-free languages

OperationClosed?

The one exception that matters most: CFL ∩ Regular = CFL

Even though intersection of two arbitrary CFLs can fail to be context-free, intersecting a CFL with a regular language always stays context-free. This asymmetry — closed under intersection-with-regular, but not under general intersection or complement — is exactly why the non-closure results above don't contradict this one: a regular language's DFA has no stack of its own to create the cross-checking power that breaks CFL closure. GATE uses this exception constantly, e.g. to build a PDA for "L is context-free, restricted to strings matching some regex" without needing to re-derive a grammar from scratch.

Why union/concatenation/star/reversal survive but intersection/complement don't

Union, concatenation, and star can each be implemented by combining PDAs "in parallel" or "in sequence" without ever needing the two machines' stacks to interact — one PDA nondeterministically simulates whichever branch is relevant. Reversal just runs the grammar's derivations backward. Intersection (of two genuine CFLs) would require synchronizing two independent stacks at once, which a single-stack PDA fundamentally cannot do — that's the structural reason the closure breaks, not just an accident of the standard counterexamples.

Practice — GATE style (original)

5 questions
Q1 Is L = {aⁿbⁿcⁿ : n ≥ 0} context-free?

No — proved not context-free via the CFL pumping lemma, since any bounded-length pumped window can only touch two of the three letter blocks, so pumping unbalances the counts.

Answer: No, not context-free

Q2 Is L = {wwᴿ : w ∈ {a,b}*} (even palindromes) accepted by a deterministic PDA?

No — while L is context-free (an NPDA can nondeterministically guess the midpoint and then match the reversal against the stack), no deterministic PDA can identify the exact midpoint without unbounded lookahead, so no DPDA accepts this language.

Answer: No — context-free but not deterministic context-free

Q3 L1 and L2 are both context-free. Is L1 ∩ L2 guaranteed to be context-free?

No — CFLs are NOT closed under intersection in general (only intersection with a regular language is guaranteed to stay context-free). A counterexample: {aⁿbⁿcᵐ} ∩ {aᵐbⁿcⁿ} = {aⁿbⁿcⁿ}, which is not context-free even though both operands are.

Answer: No, not guaranteed

Q4 Give a PDA sketch (informal) for L = {aⁿbⁿ : n≥0}.

Push a marker onto the stack for every 'a' read. On seeing the first 'b', switch to popping one marker per 'b' read. Accept if the stack is empty exactly when the input ends — any mismatch in count leaves the stack non-empty or forces a pop on an empty stack.

Answer: Push X for each 'a'; pop one X per 'b'; accept on empty stack at end of input

Q5 Is a context-free language intersected with a regular language guaranteed to be context-free?

Yes — this specific case IS closed, via a product construction combining a PDA (for the CFL) with a DFA (for the regular language), tracking both machines' states/stack together.

Answer: Yes, always context-free

05

Turing Machines

TM DEFINITION · DESIGN & TRACING · VARIANTS · CHURCH-TURING THESIS

TM — a finite automaton plus an infinite tape

A Turing machine replaces the PDA's stack with an infinite, two-way read/write tape, giving it unrestricted memory access (not just last-in-first-out). Formally a 7-tuple (Q, Σ, Γ, δ, q₀, q_accept, q_reject) where Γ⊇Σ is the tape alphabet (including a blank symbol), and δ: Q×Γ → Q×Γ×{L,R} — read a symbol, write a symbol, move the head left or right, change state.

TM tape — head reads/writes the cell under it, then moves L or R; the tape is infinite in both directions

Designing a TM — the "aⁿbⁿcⁿ" workhorse example

This exact language (not context-free, as shown in section 04) is a standard first TM design exercise, because it demonstrates why unrestricted tape access is strictly more powerful than a stack:

Repeat: Scan right, find the leftmost unmarked 'a', mark it (e.g. replace with X), remember its position Scan right past remaining a's/b's, find the leftmost unmarked 'b', mark it (Y) Scan right past remaining b's/c's, find the leftmost unmarked 'c', mark it (Z) Scan back to the start Until: no unmarked 'a' remains Accept if, at that point, no unmarked 'b' or 'c' remains either (all counts matched)

TM variants — equally powerful (with one important exception)

Multi-tape TMs, non-deterministic TMs (NTMs), and TMs with a two-way infinite tape are all equally powerful — every one of these variants recognizes exactly the same class of languages as a standard single-tape deterministic TM. But "equally powerful" is a statement about computability only, not about simulation cost, and the cost differs sharply by variant: converting a multi-tape TM to a single-tape TM costs at most a polynomial slowdown, but simulating an NTM deterministically can cost an exponential blowup in time in the worst case (see the GATE trap below — these are genuinely different overheads, don't conflate them). This equivalence is why "Turing-computable" is a single, robust notion rather than depending on which TM flavor you pick.

The exception: a TM that can only move right

A TM restricted to only ever moving its head right (never left) is not in the equally-powerful group above — it's strictly weaker. Without the ability to move back and revisit earlier tape cells, such a machine can't backtrack or re-examine what it's already read/written, and its recognizable language class collapses down to the regular languages — the same class a plain DFA recognizes. Don't lump this variant in with multi-tape/NTM/two-way-infinite-tape; it is the one common "TM variant" question where the power genuinely changes.

The Church–Turing thesis

Any function that is "effectively computable" by some intuitive step-by-step algorithmic process can be computed by a Turing machine. This is a thesis, not a theorem — it can't be formally proven since "effectively computable" isn't a rigorous mathematical object on its own, but every alternative model of computation proposed so far (lambda calculus, RAM machines, etc.) has been proven exactly equivalent in power to the TM.

GATE trap

"Non-deterministic TM is more powerful than deterministic TM" is FALSE — unlike the DPDA/NPDA case (which genuinely differ in power), NTMs and DTMs recognize exactly the same class of languages. Non-determinism only affects potential speed (an NTM can be simulated by a DTM with an exponential blowup in the worst case, relevant to complexity theory), never which languages are recognizable at all. Separately: "a TM that can only move right is just as powerful as a standard TM" is also FALSE — that restriction genuinely reduces power to regular languages, unlike multi-tape or non-determinism.

Practice — GATE style (original)

5 questions
Q1 Is a 3-tape TM strictly more powerful (recognizes more languages) than a 1-tape TM?

No — every multi-tape TM can be simulated by a single-tape TM (by interleaving the tape contents on one tape), so they recognize exactly the same class of languages. Multi-tape only helps with speed, not with what's computable at all.

Answer: No, same power (just potentially faster)

Q2 Is L = {aⁿbⁿcⁿ : n≥0}, which is not context-free, decidable by some Turing machine?

Yes — this language sits above context-free but is still well within what a TM can decide (the tape-marking algorithm sketched in this section decides it in linear-ish time, always halting with an accept/reject answer).

Answer: Yes, decidable

Q3 Does a non-deterministic TM recognize a strictly larger class of languages than a deterministic TM?

No — NTMs and DTMs are exactly equivalent in recognizing power (any NTM can be simulated by a DTM, generally with an exponential time overhead). This is unlike the DPDA vs NPDA situation one level down the hierarchy.

Answer: No, exactly the same power

Q4 Can the Church-Turing thesis be formally proven?

No — it's a thesis (a claim connecting an informal notion, "effective computability," to a formal one, "Turing-computable"), not a theorem, precisely because one side of the equivalence isn't a rigorously defined mathematical object.

Answer: No — it's a thesis, not a provable theorem

Q5 A TM's transition function is defined as δ: Q×Γ → Q×Γ×{L,R}. What three things does the machine decide in a single step?

Given the current state and the symbol under the head, δ determines: the new state to enter, the symbol to write over the current cell, and which direction to move the head.

Answer: Next state, symbol to write, and direction (L or R) to move

Decidability & Undecidability

RECURSIVE VS RE · HALTING PROBLEM · REDUCTIONS · PCP · RICE'S THEOREM

Recursive vs. recursively enumerable — the key distinction

ClassDefinitionOn a "no" input...
Recursive (decidable)Some TM always halts, correctly accepting or rejectingHalts and rejects
Recursively enumerable (Turing-recognizable)Some TM halts and accepts every string in L, but may loop forever on strings not in LMay run forever (no guaranteed "reject" signal)
The defining closure result

A language L is recursive if and only if both L and its complement L̄ are recursively enumerable. This single fact underlies most decidability proofs: if you can show a language and its complement are each RE, you get decidability for free.

The Halting Problem — the canonical undecidable problem

HALT = {⟨M,w⟩ : TM M halts on input w} is undecidable — no TM can, for every possible (M,w) pair, correctly determine in finite time whether M halts on w. The classic proof is diagonalization: assume a TM H decides HALT, construct a TM D that runs H on itself and does the opposite of what H predicts, then show D contradicts itself when run on its own description.

Reductions — proving new problems undecidable

To show a new problem P is undecidable, reduce a known undecidable problem (usually HALT) to P: show that if P were decidable, you could use that decider to build a decider for HALT — contradiction. The reduction must go in this specific direction (known-undecidable → new problem), and GATE frequently tests whether you have the direction right.

GATE trap

A reduction from A to B (A ≤ B) shows: if B is decidable, then A is decidable (equivalently: if A is undecidable, then B is undecidable). Students often reduce in the wrong direction — remember, you're using a hypothetical decider for the new problem B to build a decider for the already-known-undecidable A, which is what generates the contradiction.

The Post Correspondence Problem (PCP) — another canonical undecidable problem

Given two lists of strings A = (a₁,...,aₙ) and B = (b₁,...,bₙ) of equal length, PCP asks: does there exist a sequence of indices i₁,i₂,...,iₖ (repeats allowed, k≥1) such that a_{i₁}a_{i₂}...a_{iₖ} = b_{i₁}b_{i₂}...b_{iₖ}? In other words, can you pick tiles (each labeled with a top string from A and a bottom string from B) and lay them in some order so the concatenated top and bottom strings match exactly.

PCP is undecidable

There is no algorithm that decides, for an arbitrary pair of lists, whether a matching sequence exists. GATE doesn't expect you to reproduce the proof (it's a reduction from the Turing machine acceptance problem) — just to recognize PCP by name as a standard undecidable problem, and to know it's commonly used itself as the known-undecidable source problem when proving that certain grammar/language questions (like CFG ambiguity, or whether two CFGs' languages intersect) are undecidable, via a reduction FROM PCP.

Rice's theorem

Any non-trivial property of the language recognized by a Turing machine (i.e., a property that's true for some RE languages and false for others — not about the machine's structure/code, only about the language it recognizes) is undecidable. This single theorem instantly settles a huge number of "is this property decidable" questions without needing a custom reduction each time.

Decidable problems GATE also expects you to know

For regular languages (given DFAs/NFAs/regex), every standard question is decidable — membership, emptiness, finiteness, equivalence, inclusion, and universality all have known algorithms (minimize and compare, build a product automaton, etc.). This is a lower-hierarchy result, unaffected by Rice's theorem, which only concerns Turing machines/RE languages.

For context-free languages (given CFGs/PDAs), only some of these carry over — don't assume the whole list transfers up a level. Membership and emptiness are decidable for CFLs, but equivalence, inclusion, and universality are undecidable in general.

Practice — GATE style (original)

5 questions
Q1 Is it decidable whether two given DFAs accept the same language? Does the same hold for two given CFGs?

Yes — DFA equivalence is decidable (e.g., minimize both DFAs and compare, or build a DFA for the symmetric difference and check it accepts nothing). This is a lower-hierarchy decidability result, unaffected by Rice's theorem, which only concerns Turing machines/RE languages.

The same question for two CFGs does NOT hold — CFG (context-free language) equivalence is undecidable in general, even though CFG membership and emptiness are still decidable. Don't assume decidability carries over uniformly from regular to context-free just because both sit below the Turing-machine level.

Answer: DFA equivalence — Yes, decidable. CFG equivalence — No, undecidable.

Q2 Is it decidable whether a given Turing machine M accepts the empty language (L(M)=∅)?

No — "L(M) is empty" is a non-trivial semantic property of the language M recognizes (true for some TMs, false for others), so Rice's theorem makes it undecidable.

Answer: No, undecidable (by Rice's theorem)

Q3 Is L recursive if both L and its complement are recursively enumerable?

Yes — this is exactly the defining characterization: L is recursive if and only if L and L̄ are both RE.

Answer: Yes, L is recursive

Q4 Is it decidable whether a given Turing machine's description contains exactly 10 states?

Yes — this is a purely syntactic property of the machine's own description (easily checked by counting), not a semantic property of the language it recognizes, so Rice's theorem does not apply and it's straightforwardly decidable.

Answer: Yes, decidable (syntactic, not a language property)

Q5 To prove a new problem P is undecidable via reduction from HALT, which direction must the reduction go?

You must show HALT ≤ P (reduce HALT to P): assume a decider for P exists, and use it to build a decider for HALT. Since HALT is already known undecidable, this is a contradiction, proving P is undecidable too.

Answer: Reduce HALT to P (HALT ≤ P), not the other way around

Revision Sheet

EVERYTHING ON ONE SCREEN — LAST-MINUTE PASS
Chomsky hierarchy (power)

Regular ⊂ Context-free ⊂ Recursive ⊂ Recursively enumerable — each strictly more powerful than the last.

NFA = DFA in power

Subset construction converts any NFA to an equivalent DFA (up to 2ⁿ states) — same expressive power, only worst-case state count differs.

Kleene's theorem

Regular ⟺ some FA accepts it ⟺ some regex describes it. All three are interchangeable.

Pumping lemma = disproof tool only

Both the regular and CFL pumping lemmas prove a language is NOT in that class. Neither can ever prove membership.

Regular PL split

w=xyz, |xy|≤p, |y|≥1, xyⁱz∈L for all i≥0.

CFL PL split

w=uvxyz, |vxy|≤p, |vy|≥1, uvⁱxyⁱz∈L for all i≥0 — TWO pieces pumped together.

DPDA ⊊ NPDA (unlike NFA=DFA)

Deterministic PDAs are strictly weaker. wwᴿ is context-free but not deterministic context-free.

NTM = DTM in power

Unlike DPDA/NPDA, non-determinism never adds recognizing power to a Turing machine — only affects speed.

CFL closure

Closed under union, concatenation, star, reversal, and intersection-with-regular. NOT closed under CFL∩CFL, complement, or difference.

CFL decidability — don't over-extend from regular

Membership, emptiness, and finiteness ARE decidable for CFLs. Equivalence, inclusion, and universality are UNDECIDABLE for CFLs — unlike for regular languages, where all six are decidable.

PCP

The Post Correspondence Problem (matching tile sequences from two string lists) is undecidable — a second named canonical undecidable problem alongside HALT, often used as a reduction source.

CNF derivation length

A CNF parse tree derives a length-n string using exactly 2n−1 production applications.

Recursive vs RE

Recursive = TM always halts (accept or reject). RE = TM halts and accepts on "yes," may loop forever on "no."

L recursive ⟺ L, L̄ both RE

The single most reusable decidability fact — check both directions to get decidability for free.

Rice's theorem

Any non-trivial property of L(M) is undecidable. Syntactic properties of M's own description (state count, etc.) are NOT covered — those are decidable.

Reduction direction

To prove P undecidable: reduce a KNOWN-undecidable problem (e.g. HALT) TO P. Never the reverse direction.

ε vs ∅

ε = empty string (a valid, zero-length match). ∅ = empty language (no strings at all, not even ε).

Practice — rapid-fire mix (original)

5 questions
Q1 Is L = {a^n : n is a perfect square} regular?

No — using the pumping lemma with pumping length p, choose w = a^(p²) (this is valid regardless of whether p itself is a perfect square, since p² always is). For any decomposition satisfying |xy| ≤ p and |y| > 0, y = a^k with 1 ≤ k ≤ p. Pumping down once (i = 0) gives length p² − k. Since (p−1)² = p² − 2p + 1 and 1 ≤ k ≤ p, we get p² − 2p + 1 < p² − k < p², so p² − k lies strictly between the consecutive perfect squares (p−1)² and p², and is therefore not itself a perfect square — contradicting the pumping lemma.

Answer: No, not regular

Q2 A grammar has the rule set S→aSb|bSa|SS|ε. Is the language generated context-free?

Yes trivially — anything generated by a CFG is by definition context-free; the question of interest here would be ambiguity or exactly which strings it generates, not whether it's context-free (it is, by construction).

Answer: Yes, context-free by definition

Q3 Is the language L = {⟨M⟩ : M is a TM that halts on the empty string} decidable?

No — this is essentially the halting problem restricted to a fixed input (empty string), and it's still undecidable via a reduction from the general halting problem.

Answer: No, undecidable

Q4 True or false: every regular language is also context-free.

True — the Chomsky hierarchy is a strict containment, regular ⊂ context-free, so every regular language can also be generated by some CFG (in fact, every regular language has a right-linear/left-linear grammar, which is a restricted CFG).

Answer: True

Q5 Is checking whether a given CFG is ambiguous decidable?

No — determining whether an arbitrary CFG is ambiguous is undecidable in general (a well-known undecidable problem in the theory, distinct from but related to Rice's-theorem-style results at the Turing machine level).

Answer: No, undecidable in general
