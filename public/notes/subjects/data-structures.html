Recursion

BASE CASE · RECURSIVE CASE · CALL STACK · TAIL RECURSION

How recursion works

A recursive function is one that calls itself to solve a smaller instance of the same problem. It consists of two parts:

  • Base case: The terminating condition that stops the recursion.
  • Recursive case: The part where the function calls itself with modified parameters that move toward the base case.

Every recursive call pushes a new frame onto the call stack containing local variables and return addresses. When the base case is reached, the stack unwinds, resolving the calls in reverse order (LIFO).

Tail recursion

A recursive function is tail-recursive if the recursive call is the very last operation performed in the function (nothing is evaluated after the recursive call returns). A compiler or runtime may perform tail-call optimization (TCO) — reusing the current stack frame instead of pushing a new one — which turns the recursion into effectively O(1) stack space. But this is an optimization the implementation chooses to do, not a guarantee of the language: C does not require TCO, and whether a given compiler actually performs it depends on the compiler and the optimization flags used (e.g. gcc often does it only at -O2/-O3, not at -O0). Don't conclude that tail-recursive C code necessarily uses O(1) stack space — without confirmed TCO, it still uses O(n) stack space like any other recursion, and can still overflow the stack.

Recurrence relations

The time complexity of a recursive function is often modeled as T(n) = aT(n/b) + f(n). The Master Theorem provides direct solutions for this form.

Space complexity = O(maximum depth of the recursion tree) Due to the call stack, even if the time complexity is O(n), the space complexity can be O(n) for a linear recursive chain.
Converting recursion to iteration

Any recursive algorithm can be converted into an iterative one by using an explicit Stack data structure to simulate the call stack.

GATE trap

Missing base cases or base cases that are never reached lead to infinite recursion and a stack overflow. Also, GATE frequently tests whether a function is tail-recursive. `return n * fact(n-1)` is NOT tail-recursive because the multiplication happens after the recursive call returns.

Practice — GATE style (original)

5 questions
Q1 What is the time and space complexity of the standard recursive factorial function `fact(n)`?

The recurrence is T(n) = T(n-1) + O(1), leading to O(n) time. The recursion depth is n, so the call stack takes O(n) space.

Answer: Time O(n), Space O(n)

Q2 Consider `fib(n) = fib(n-1) + fib(n-2)`. What is the time complexity and space complexity?

The time complexity is O(2ⁿ) due to overlapping subproblems (the recursion tree has ~2ⁿ nodes). The space complexity is O(n) because the maximum depth of the call stack is n.

Answer: Time O(2ⁿ), Space O(n)

Q3 Is the function `void print(int n) { if(n==0) return; print(n-1); printf("%d", n); }` tail recursive?

No, because the `printf` statement executes after the recursive call `print(n-1)` returns. The recursive call is not the last operation.

Answer: No

Q4 What is the recurrence relation for the classic Tower of Hanoi problem with n disks?

To move n disks, we move n-1 disks to an auxiliary peg, move the nth disk to the destination, and then move the n-1 disks to the destination. T(n) = 2T(n-1) + 1.

Answer: T(n) = 2T(n-1) + 1

Q5 A recursive function splits an array of size n into two halves, recursively processes each half, and does O(n) work to combine. What is the maximum depth of the recursion tree?

The problem size halves at each step: n, n/2, n/4, ..., 1. The depth of this division is log₂(n).

Answer: O(log n)

02

Arrays

CONTIGUOUS MEMORY · RANDOM ACCESS · DYNAMIC ARRAYS · 2D ARRAYS

Array properties

Arrays allocate memory in a contiguous block. Because elements are contiguous and of fixed size, arrays provide O(1) random access by computing the memory address directly:

Address(A[i]) = Base_Address + (i - lower_bound) × element_size

Operations complexity:

  • Access: O(1)
  • Search (unsorted): O(n)
  • Search (sorted): O(log n) via binary search
  • Insert/Delete: O(n) because elements must be shifted to maintain contiguity.

2D Array addressing

For a 2D array A[lr..ur][lc..uc] where `lr` and `lc` are the lower bounds for rows and columns, `Nr = ur - lr + 1` is the number of rows, and `Nc = uc - lc + 1` is the number of columns:

Row-major order
Address(A[i][j]) = Base + ((i - lr) × Nc + (j - lc)) × size
Column-major order
Address(A[i][j]) = Base + ((j - lc) × Nr + (i - lr)) × size
Dynamic arrays

Standard arrays have a fixed size. Dynamic arrays (like C++ vector, Java ArrayList) allocate a new contiguous block of double the size when full. This "doubling strategy" yields an amortized insertion time complexity of O(1) per element.

GATE trap

In 2D addressing formulas, remember to multiply by the number of columns `Nc` for Row-Major (because you skip full rows of length `Nc`), and by the number of rows `Nr` for Column-Major. Off-by-one errors with `lr` and `lc` are common—assume 0-indexing unless the problem specifies 1-indexing or explicit bounds.

Practice — GATE style (original)

5 questions
Q1 Given a 2D array A[1..10][1..15] stored in row-major order with base address 100 and element size 4 bytes, find the address of A[8][6].

lr=1, lc=1, Nc=15. Address = 100 + ((8-1)×15 + (6-1))×4 = 100 + (7×15 + 5)×4 = 100 + (105+5)×4 = 100 + 440 = 540.

Answer: 540

Q2 Given the same array A[1..10][1..15], find the address of A[8][6] if stored in column-major order.

lr=1, lc=1, Nr=10. Address = 100 + ((6-1)×10 + (8-1))×4 = 100 + (5×10 + 7)×4 = 100 + 57×4 = 100 + 228 = 328.

Answer: 328

Q3 What is the amortized time complexity of appending an element to a dynamic array that doubles its capacity when full?

n appends trigger reallocations at powers of 2. Total cost to append n elements is roughly n + (1 + 2 + 4 + ... + n) ≤ 3n = O(n). Divided by n operations, the amortized cost is O(1).

Answer: O(1)

Q4 Consider an array of size n containing elements from 1 to n-1 with exactly one duplicate. What is the time complexity to find the duplicate using only O(1) extra space?

You can sum the elements and subtract the sum of 1 to n-1, or use Floyd's cycle-finding algorithm by treating elements as next pointers. Both take O(n) time and O(1) space.

Answer: O(n)

Q5 An array `A[-5..5][0..10]` is given. How many elements are in this array?

Number of rows = 5 - (-5) + 1 = 11. Number of columns = 10 - 0 + 1 = 11. Total elements = 11 × 11 = 121.

Answer: 121

Linked Lists

SINGLY · DOUBLY · CIRCULAR · OPERATIONS COMPLEXITY

Variations

Linked lists are dynamic collections of nodes where each node points to the next, sacrificing random access in exchange for cheap insertion/deletion — but "O(1) if the location is known" needs a caveat that depends on which kind of list and which node.

  • Singly Linked List: Node = data + next pointer. Traversal is one-way. Insertion/deletion at head is O(1). Deleting an arbitrary given node normally needs its predecessor's pointer (to relink next), not just a pointer to the node itself — so "O(1) deletion given a node pointer" doesn't hold for singly linked lists unless you also have the predecessor, or you use the copy-next-node trick (copy the next node's data into the target node, then delete the next node instead) — which fails if the target is the tail. Finding an arbitrary node is O(n).
  • Doubly Linked List: Node = prev + data + next pointer. Allows backward traversal. Deleting a given node pointer is genuinely O(1) here, since the node itself carries a pointer to its predecessor — no separate traversal or trick needed.
  • Circular Linked List: The next pointer of the last node points back to the first node. Used in round-robin scheduling algorithms.

Array vs Linked List Comparison

OperationArrayLinked List
Random AccessO(1)O(n)
Insert at HeadO(n)O(1)
Delete at EndO(1)O(n) (singly, without tail ptr)
Memory overheadNoneO(n) for pointers

Classic Algorithms

Cycle Detection (Floyd's Tortoise and Hare)

Use two pointers: slow (moves 1 step) and fast (moves 2 steps). If there is a cycle, they will eventually meet. Time: O(n), Space: O(1).

Middle of Linked List

Use two pointers: slow (1 step) and fast (2 steps). When fast reaches the end, slow is at the middle. Time: O(n), Space: O(1).

Reversing a Singly Linked List

Maintain three pointers: prev (initially NULL), curr (initially head), and next. Traverse the list, changing curr->next = prev, then shifting all three pointers one step forward.

GATE trap

When inserting or deleting nodes, the order of pointer assignments is critical. If you overwrite a node's `next` pointer before saving it, you lose the rest of the list (memory leak). Always handle edge cases: empty list (`head == NULL`) and single-node list.

Practice — GATE style (original)

5 questions
Q1 Given a pointer to a node (not the tail) in a singly linked list, what is the time complexity to delete it?

Normally O(n) because you need the previous node. However, if node identity is irrelevant and the node is not the tail, the standard data-copying trick can remove its value from the list in O(1): copy the next node's data into the current node, then delete the next node. Strictly speaking, the supplied node itself is not freed — its contents are replaced by those of its successor, and the successor's node is the one actually deallocated. This distinction matters if nodes have identity, external pointers reference the original node, the node holds metadata/resources, or the successor isn't semantically interchangeable.

Answer: O(1) (with the data-copying trick)

Q2 In a circular singly linked list, what is the time complexity to insert a new node at the head if we only have a pointer to the head?

To insert at the head, the last node's next pointer must be updated to point to the new head. Finding the last node requires traversing the whole list. Thus, O(n). (If a tail pointer is maintained, it becomes O(1)).

Answer: O(n)

Q3 What are the correct steps to insert a new node `N` between `A` and `B` in a singly linked list?

First attach N to the rest of the list: `N->next = A->next;`. Then attach A to N: `A->next = N;`. If done in reverse, the pointer to B is lost.

Answer: N->next = A->next; A->next = N;

Q4 In Floyd's cycle detection algorithm, if the list length is N and the cycle length is C, what is the asymptotic time complexity (number of steps) before the pointers meet?

The slow pointer enters the cycle after at most N-C steps. Once both are in the cycle, the distance between them decreases by 1 each step. The maximum distance is C-1, so they meet after at most N-C + (C-1) = N-1 steps, i.e. O(N) total steps. At GATE level, O(N) is the expected answer since N ≥ C always. If you want the tighter, more precise bound used when analyzing Floyd's algorithm itself (rather than just bounding by list length), it's usually written O(μ + λ), where μ is the length of the non-cyclic "tail" before the cycle starts and λ is the cycle length — this is the same quantity as N-C and C-1 above, just named differently.

Answer: O(N) time (equivalently O(μ + λ))

Q5 How many pointers need to be modified to delete a node in a doubly linked list (assuming it is not the head or tail)?

Two pointers must be updated: `node->prev->next = node->next;` and `node->next->prev = node->prev;`.

Answer: 2 pointers

Stacks

LIFO · PUSH/POP · APPLICATIONS · STACK USING ARRAY/LL

LIFO principle

A stack is a linear data structure following the Last In, First Out (LIFO) principle. The operations push, pop, and peek all operate on the top element in O(1) time.

Implementation

Array-based: Uses a fixed-size array and a top pointer (initially −1). Pushing increments top; popping decrements it. Causes overflow if full.

Linked-list-based: Uses a singly linked list. Push and pop operations are performed at the head of the list to ensure O(1) time complexity.

Applications

  • Parenthesis matching and syntax parsing
  • Expression conversion (infix to postfix/prefix)
  • Postfix expression evaluation
  • Function call stack (recursion)
  • Undo mechanisms in text editors

Infix to postfix conversion

Operands are added to the output immediately. Operators are pushed to the stack based on precedence and associativity. A higher precedence operator can be pushed on top of a lower one. If precedence is equal, associativity (left-to-right or right-to-left) determines the action.

Postfix evaluation

Scan the expression left to right. Push operands to the stack. When an operator is encountered, pop the top two operands (first pop is right operand, second is left), apply the operator, and push the result back.

Complexity
OperationArrayLinked List
PushO(1)O(1)
PopO(1)O(1)
Peek/TopO(1)O(1)
GATE trap

Associativity trap: While converting infix to postfix, operators like ^ (exponentiation) are right-associative. You can push ^ on top of another ^ in the stack! Also, watch out for stack underflow (popping an empty stack), which GATE often tests in sequence-of-operations questions.

Practice — GATE style (original)

5 questions
Q1 Evaluate postfix expression: 5 3 + 8 2 / *

Push 5, 3. Encounter '+': pop 3, 5, compute 5+3=8, push 8. Stack: [8]. Push 8, 2. Encounter '/': pop 2, 8, compute 8/2=4, push 4. Stack: [8, 4]. Encounter '*': pop 4, 8, compute 8*4=32, push 32.

Answer: 32

Q2 In infix to postfix, when is an operator popped from the stack?

When the incoming operator has lower precedence, or equal precedence and left-to-right associativity, compared to the operator at the top of the stack.

Answer: Lower precedence or equal precedence with L-to-R associativity

Q3 How many distinct binary trees can be formed with 3 unlabelled nodes, which also equals the number of stack permutations?

This is given by the Catalan number Cₙ = (2n)! / ((n+1)! * n!). For n=3, C₃ = 6! / (4! * 3!) = 720 / (24 * 6) = 5.

Answer: 5

Q4 To check balanced parentheses for "{ [ ( ) ] }", what is the maximum depth of the stack?

Push '{' (depth 1), push '[' (depth 2), push '(' (depth 3). Next is ')', pop '('. Max depth reached is 3.

Answer: 3

Q5 If we implement a stack using a singly linked list, which end should be the 'top' for O(1) operations?

The head of the linked list. Pushing at the head is O(1) and popping at the head is O(1). If we used the tail, pushing might be O(1) with a tail pointer, but popping would be O(n) as we need to find the new tail.

Answer: The head of the linked list

Queues

FIFO · CIRCULAR QUEUE · DEQUE · PRIORITY QUEUE

FIFO principle

A queue follows the First In, First Out (FIFO) principle. Elements are inserted at the rear and removed from the front. Enqueue, dequeue, front, and rear operations are all O(1).

Linear vs Circular Queue

In a linear array-based queue, dequeuing elements leaves empty spaces at the front that cannot be reused without shifting elements (which is O(n)). This wasted space problem is solved by the circular queue, where the rear pointer wraps around to the beginning of the array.

Circular Queue Implementation

Using an array of size n, with modular arithmetic:

Enqueue: rear = (rear + 1) % n Dequeue: front = (front + 1) % n

Distinguishing Full from Empty:

  • Sacrifice one slot: Queue is full when (rear + 1) % n == front. Empty when front == rear (or front == -1). Array holds max n−1 elements.
  • Size counter: Keep a count variable. Full when count == n. Empty when count == 0. Allows holding n elements.

Deque (Double-ended queue)

Allows insertion and deletion from both ends (front and rear). Can act as both a stack and a queue.

Priority Queue

An abstract data type where each element has a priority. Elements with higher priority are dequeued before those with lower priority. Typically implemented using a Heap (covered in section 08) for O(log n) operations.

GATE trap

Off-by-one errors: Pay strict attention to initial conditions (e.g., front=0, rear=n−1 vs front=−1, rear=−1). GATE questions on circular queues often exploit the ambiguity between full and empty states if a counter isn't used — always check if the question implies leaving one slot empty!

Practice — GATE style (original)

5 questions
Q1 A circular queue of size n=5 has front=2, rear=4 (assume rear points to the last occupied slot, not the next free slot — the convention used consistently across all circular-queue questions on this page). If we enqueue one element, what are the new front and rear?

Enqueue changes rear: rear = (4 + 1) % 5 = 0. Front remains 2.

Answer: front=2, rear=0

Q2 How many stacks are minimally required to implement a queue?

Two stacks are required. One stack handles enqueues, and the other handles dequeues (elements are transferred when the dequeue stack is empty).

Answer: 2

Q3 In a circular queue using an array of size n, leaving one slot empty, what is the maximum number of elements it can hold?

To distinguish between full and empty without a counter, one slot must remain unused. Thus, capacity is n−1.

Answer: n−1

Q4 A deque supports insertFront, insertRear, deleteFront, deleteRear. Which two operations restrict it to behave as a normal stack?

To act as a stack, all insertions and deletions must happen at the same end. For example, using only insertFront and deleteFront.

Answer: insertFront and deleteFront (or insertRear and deleteRear)

Q5 If a queue is implemented with a singly linked list with head and tail pointers, what is the complexity of enqueue and dequeue?

Enqueue at the tail using the tail pointer is O(1). Dequeue at the head using the head pointer is O(1).

Answer: Both O(1)

Trees

TERMINOLOGY · BINARY TREES · TRAVERSALS · PROPERTIES

Terminology

A tree is an undirected, acyclic, connected graph. Key terms: root (top node), parent/child/sibling, leaf (node with 0 children), depth (edges from root to node), height (edges from node to deepest leaf), level (all nodes at same depth).

Binary Trees

Each node has at most 2 children. Types:

  • Full/Strict: Every node has 0 or 2 children.
  • Complete: All levels are completely filled except possibly the last, which is filled from left to right.
  • Perfect: All internal nodes have 2 children, and all leaves are at the same level.
  • Skewed: Every node has at most 1 child (essentially a linked list).
Properties & Formulas (Root at level 0)
Max nodes at level i = 2ⁱ Max nodes in tree of height h = 2ʰ⁺¹ − 1 Min height for n nodes = ⌊log₂ n⌋ Max height for n nodes = n − 1 Leaves (n₀) and degree-2 nodes (n₂) relation: n₀ = n₂ + 1 Number of NULL pointers in a binary tree with n nodes = n + 1

Traversals

Depth-First Traversals (recursive):

  • Inorder (Left, Root, Right): Gives sorted order for a Binary Search Tree (BST).
  • Preorder (Root, Left, Right): Used for tree copying/serialization.
  • Postorder (Left, Right, Root): Used for tree deletion or postfix expression evaluation.

Breadth-First Traversal: Level-order uses a queue to visit nodes level by level.

Constructing Tree from Traversals

To uniquely reconstruct an arbitrary binary tree, you need the inorder traversal paired with either the preorder or postorder traversal. Preorder and postorder alone are not sufficient for arbitrary binary trees — without inorder, there isn't enough information to tell which side of a node a given subtree belongs on whenever a node has only one child.

GATE trap — the full-binary-tree exception

The insufficiency above specifically comes from nodes with exactly one child: preorder+postorder can't tell you whether that one child is a left child or a right child. This ambiguity disappears entirely if the tree is a full (a.k.a. strict) binary tree — every node has either 0 or 2 children, never exactly 1. For a full binary tree with distinct node labels, preorder + postorder together ARE sufficient to uniquely reconstruct the tree — no inorder needed. Don't answer "preorder+postorder is never enough" as an unqualified blanket statement; GATE specifically likes testing whether you know this exception applies once the "full/strict" condition is stated.

GATE trap

Height vs Depth Convention: Be very careful! Some GATE questions define the height of a single-node tree as 0 (counting edges), while others define it as 1 (counting nodes). Read the question carefully to determine their convention. Also, the formula n₀ = n₂ + 1 is valid only for binary trees, not general trees!

Practice — GATE style (original)

5 questions
Q1 In a binary tree, if the number of internal nodes with 2 children is 15, how many leaf nodes are there?

Using the property n₀ = n₂ + 1, the number of leaf nodes n₀ = 15 + 1 = 16.

Answer: 16

Q2 Which two traversals are necessary and sufficient to uniquely reconstruct an arbitrary binary tree — and is there an exception?

For an arbitrary binary tree, inorder traversal must be paired with either preorder or postorder traversal — preorder and postorder together cannot uniquely determine an arbitrary binary tree without inorder, because a node with exactly one child leaves the tree ambiguous as to which side that child is on. The exception: if the tree is known to be a full/strict binary tree (every node has 0 or 2 children, distinct labels), preorder + postorder alone ARE sufficient — the one-child ambiguity that inorder would normally resolve simply can't occur.

Answer: Inorder and (Preorder OR Postorder) for arbitrary binary trees — but Preorder + Postorder alone suffice if the tree is guaranteed full/strict

Q3 What is the maximum number of nodes in a binary tree of height h (where a single node has height 0)?

A perfect binary tree of height h has 2⁰ + 2¹ + ... + 2ʰ = 2ʰ⁺¹ − 1 nodes.

Answer: 2ʰ⁺¹ − 1

Q4 How many NULL pointers exist in a binary tree with 100 nodes?

A binary tree with n nodes has exactly n + 1 NULL pointers. For n=100, there are 101 NULL pointers.

Answer: 101

Q5 If the inorder traversal of a BST is 'A B C D E', what can we say about the elements?

Inorder traversal of a Binary Search Tree always visits the nodes in sorted (ascending) order. Therefore, A < B < C < D < E.

Answer: The elements are sorted: A < B < C < D < E

Binary Search Trees

BST PROPERTY · SEARCH/INSERT/DELETE · BALANCING · AVL TREES

BST property

For every node, all values in its left subtree are less than the node's value, and all values in its right subtree are greater than the node's value.

left subtree < root < right subtree (for all nodes recursively)

An inorder traversal of a BST always visits the nodes in sorted (ascending) order.

Operations & complexities

  • Search: Compare with root, go left if smaller or right if larger — O(h) where h = height.
  • Insert: Search for position, insert as leaf — O(h).
  • Delete: 3 cases:
    • Leaf node: just remove it.
    • One child: replace node with its child.
    • Two children: replace node with its inorder predecessor (max in left subtree) or inorder successor (min in right subtree), then recursively delete that node.

Balanced vs unbalanced: In the worst case (skewed tree), operations are O(n). In a balanced tree, operations are O(log n).

BST operation complexity — don't drop the worst case
OperationBalanced BST (e.g. AVL)Unbalanced/skewed BST (worst case)
SearchO(log n)O(n)
InsertO(log n)O(n)
DeleteO(log n)O(n)

A plain BST offers no guarantee of O(log n) — that bound holds only once the tree is height-balanced (h = O(log n)), which is exactly what self-balancing schemes like AVL and Red-Black trees exist to enforce. A GATE question that just says "BST" (not "balanced BST" or "AVL tree") should be read as potentially skewed — O(h) is the honest general answer, and h can be as large as n−1.

AVL Trees

Balance factor — definition, valid range, and rebalancing trigger
BF(v) = height(left subtree of v) − height(right subtree of v)

For a valid AVL tree, every node must satisfy BF ∈ {−1, 0, +1}. After an insertion or deletion, if any node ends up with |BF| > 1 (i.e. BF = +2 or BF = −2), that node is unbalanced and requires rebalancing via one of the four rotation cases below — which specific case depends on both the sign of the unbalanced node's own BF and the sign of its heavier child's BF.

When an insertion or deletion violates the balance factor, rotations are applied:

  • LL (Left-Left): Requires right rotation.
  • RR (Right-Right): Requires left rotation.
  • LR (Left-Right): Requires left rotation on child, then right rotation on parent.
  • RL (Right-Left): Requires right rotation on child, then left rotation on parent.
AVL rotation lookup — quick recall table
Imbalance caseRotation to apply
LL (inserted into left subtree of left child)Single Right rotation
RR (inserted into right subtree of right child)Single Left rotation
LR (inserted into right subtree of left child)Left rotation on the child, then Right rotation on the parent
RL (inserted into left subtree of right child)Right rotation on the child, then Left rotation on the parent

Mnemonic: the case name tells you which two rotations to chain — "LR" means Left first (on the child), then Right (on the parent); "RL" means Right first, then Left. The single-letter cases (LL, RR) need only the opposite single rotation.

Height of an AVL tree with n nodes is O(log n), specifically bounded between log₂(n+1) and ≈1.44·log₂(n+2). The minimum nodes N(h) for an AVL tree of height h (using the convention that a single node has height 0, matching the rest of this page):

N(h) = N(h−1) + N(h−2) + 1 (Fibonacci-like sequence), with base cases N(0) = 1, N(1) = 2
GATE trap

In deletion with two children, GATE might test if you know that choosing the inorder predecessor vs successor results in a valid BST (both do). Also, for AVL rotations, the direction of rotation (left vs right) and the node around which rotation happens is a classic MCQ. Always draw the 3 nodes involved in the imbalance.

Practice — GATE style (original)

5 questions
Q1 The number of possible BSTs with n distinct keys is?

It is given by the nth Catalan number: C(2n, n) / (n+1).

Answer: Catalan number

Q2 In a BST, finding the minimum element takes what time in the worst case?

The minimum element is the leftmost node. In a skewed BST, this can be at the deepest level h=n−1. Time is O(h) which is O(n) in worst case.

Answer: O(n)

Q3 What is the minimum number of nodes in an AVL tree of height 4? (Using the convention that a single node has height 0, consistent with the rest of this page.)

N(0) = 1, N(1) = 2. N(2) = N(1) + N(0) + 1 = 2 + 1 + 1 = 4. N(3) = N(2) + N(1) + 1 = 4 + 2 + 1 = 7. N(4) = N(3) + N(2) + 1 = 7 + 4 + 1 = 12.

Answer: 12

Q4 When deleting a node with two children in a BST, which node can replace it?

Either the inorder predecessor (maximum value in the left subtree) or the inorder successor (minimum value in the right subtree).

Answer: Inorder predecessor or inorder successor

Q5 An AVL tree becomes unbalanced after an insertion. The node causing the imbalance was inserted into the left subtree of the right child of the unbalanced node. Which rotation is needed?

This is a Right-Left (RL) case. It requires a right rotation on the right child followed by a left rotation on the unbalanced node.

Answer: RL rotation

08

Binary Heaps

COMPLETE BINARY TREE · MIN/MAX HEAP · HEAPIFY · HEAP SORT

Heap property

A heap is a complete binary tree satisfying the heap property:

  • Max-heap: parent value ≥ children's values. Root contains the maximum element.
  • Min-heap: parent value ≤ children's values. Root contains the minimum element.

Array representation

Since it is a complete binary tree, it can be efficiently represented in an array without pointers.

0-indexed array: Parent of i = ⌊(i−1)/2⌋ Left child of i = 2i + 1 Right child of i = 2i + 2 1-indexed array: Parent of i = ⌊i/2⌋ Left child of i = 2i Right child of i = 2i + 1

Operations

  • Insert: Add at the end of the array, then bubble up (heapify up) to restore property — O(log n).
  • Extract-min/max: Replace root with the last element, reduce size, and bubble down (heapify down) — O(log n).
  • Decrease/increase key: Modify the value, then bubble up or down as needed — O(log n).
  • Build heap from array: Apply heapify down starting from the last non-leaf node (index n/2 - 1 down to 0) — O(n).

Heap sort

Build a max-heap from the array, then repeatedly extract the max and place it at the end. Time complexity is O(n log n). It is an in-place sorting algorithm but it is not stable.

A Priority Queue is an abstract data type usually implemented using a heap.

Consolidated complexity sheet — standard binary heap (array-backed)

All complexities below assume a standard binary heap (array-backed, complete binary tree). Different heap variants (binomial, Fibonacci, pairing) have different amortized bounds — don't carry these numbers over to them.

GATE trap — build-heap is O(n), and here's why the "obvious" reasoning is wrong

The tempting (wrong) argument: "n insertions × O(log n) per insertion = O(n log n)." That bound is correct only for building a heap via repeated single insertion — inserting one element at a time into a growing heap really does cost O(n log n) total.

Bottom-up build-heap (heapify-down starting from the last non-leaf node up to the root) is a different algorithm with a different bound: it's O(n) because most nodes sit near the leaves, where a sift-down has almost no distance to travel. Roughly n/2 nodes do O(1) work, n/4 nodes do O(2) work, n/8 nodes do O(3) work, and so on — summing height×count over all levels gives a series that converges to O(n), not O(n log n). Also remember: heap sort is NOT a stable sort, and heap search takes O(n) time — heaps aren't built for searching.

repeated insertion (n calls to insert) → O(n log n) bottom-up build-heap (heapify from n/2−1 down to 0) → O(n)

Practice — GATE style (original)

5 questions
Q1 What is the index of the last non-leaf node in a 0-indexed heap of size n?

The last node is at index n−1. Its parent is ⌊((n−1)−1)/2⌋ = ⌊(n−2)/2⌋ = ⌊n/2⌋ − 1.

Answer: ⌊n/2⌋ − 1

Q2 True or False: Heap sort is a stable sorting algorithm.

Heap sort is not stable because operations on the heap can change the relative order of equal elements.

Answer: False

Q3 Finding the maximum element in a min-heap takes what time?

In a min-heap, the maximum element must be one of the leaf nodes. There are ceil(n/2) leaf nodes, so we must check all of them.

Answer: O(n)

Q4 What is the time complexity to build a heap from an array of n elements?

Building a heap bottom-up takes linear time because most nodes are near the bottom and have small heights to sift down.

Answer: O(n)

Q5 A max-heap contains elements [50, 30, 20, 10, 5]. After extracting the maximum element, what is the new array?

Replace root (50) with last element (5). Array: [5, 30, 20, 10]. Heapify down 5: swap with max child (30). Array: [30, 5, 20, 10]. Heapify down 5: swap with max child (10). Array: [30, 10, 20, 5].

Answer: [30, 10, 20, 5]

Breadth-First Search (BFS)

Explores level-by-level using a queue. Time: O(V+E) for adjacency list, O(V²) for matrix.

  • Applications: shortest path in unweighted graph, connected components in an undirected graph, bipartite check, level-order traversal.

Depth-First Search (DFS)

Explores deep first using a stack (or recursion). Time: O(V+E) for adjacency list, O(V²) for matrix.

  • Applications: cycle detection, topological sort (DAGs), connected components in an undirected graph, reachability and strongly connected components in a directed graph (Kosaraju/Tarjan).
"Connected components" isn't the same question once edges have direction

"Connected components" (via BFS or DFS) is inherently an undirected-graph notion — it asks which vertices can reach each other ignoring edge direction entirely. In a directed graph, the analogous questions split into two genuinely different concepts: reachability (can vertex u reach vertex v, respecting edge direction?) and strongly connected components (maximal sets of vertices that can ALL reach each other, respecting direction) — computed via Kosaraju's or Tarjan's algorithm, not a plain BFS/DFS component scan.

Cycle detection — the undirected/directed distinction

Undirected graph

During DFS, a cycle exists if you encounter an already-visited neighbor that is NOT the immediate parent you just came from. (Simply seeing "a visited neighbor" isn't enough — the edge straight back to your own parent is normal in a tree/DFS traversal, not a cycle.)

Directed graph

During DFS, a cycle exists if you encounter an edge to a node that is currently on the recursion stack (a "gray" node, still being processed) — this is a back edge. An edge to an already-fully-finished ("black") node is NOT a cycle; it's a cross or forward edge.

Why the two rules differ

In an undirected graph, every edge is inherently bidirectional, so the edge you just traversed to reach the current node always "points back" at its parent — that back-pointer is expected and must be explicitly excluded, or every single tree edge would incorrectly register as a cycle. In a directed graph, edges only go one way, so there's no symmetric "parent edge" to exclude — instead, the three-color (white/gray/black) recursion-stack membership test is what correctly separates a genuine cycle (back edge, to a gray/in-progress node) from a harmless cross or forward edge (to a black/already-finished node).

GATE trap

Mix-ups between BFS and DFS applications are common, but "shortest path = BFS" is only true in a specific setting — don't over-generalize it. Precisely: BFS gives shortest paths only in an unweighted graph (or one where every edge has equal weight), because BFS explores in layers of equal "distance" (edge count) and that only corresponds to true shortest distance when every edge costs the same. For weighted graphs, BFS's level order says nothing about path weight — you need Dijkstra's algorithm for non-negative edge weights, or Bellman-Ford if any edge weight can be negative (and to detect negative-weight cycles). Topological sort / cycle detection = DFS. Also, pay attention to graph representation — if a question assumes adjacency matrix, DFS/BFS is O(V²), not O(V+E). Handshaking lemma is tested frequently via degree sequences.

Practice — GATE style (original)

5 questions
Q1 An undirected graph has 10 vertices, each of degree 3. How many edges does it have?

By Handshaking Lemma, ∑ degrees = 2|E|. 10 × 3 = 30 = 2|E| ⇒ |E| = 15.

Answer: 15 edges

Q2 Which graph traversal algorithm is used to find the shortest path in an unweighted graph?

BFS visits nodes level by level, ensuring that the first time a node is reached, it is via the shortest path.

Answer: BFS (Breadth-First Search)

Q3 What is the maximum number of edges in an undirected bipartite graph with V vertices?

Maximized when vertices are split as evenly as possible between the two partitions: ⌊V/2⌋ in one, ⌈V/2⌉ in the other (equal halves only when V is even; for odd V they differ by one). Max edges = ⌊V/2⌋ × ⌈V/2⌉ = ⌊V²/4⌋.

Answer: ⌊V²/4⌋

Q4 How can you detect a cycle in a directed graph, and how does that differ from cycle detection in an undirected graph?

Directed: use DFS with a three-color / recursion-stack scheme — if you find an edge to a node currently on the recursion stack (a back edge to a "gray" node), a cycle exists.

Undirected: a different check is needed, because every edge is bidirectional and would otherwise falsely flag the edge straight back to your own parent as a cycle. Instead, during DFS, a cycle exists only if you reach an already-visited neighbor that is NOT the immediate parent you arrived from.

Answer: Directed — DFS back edge to a node on the recursion stack. Undirected — DFS reaches a visited neighbor that isn't the parent.

Q5 What is the time complexity to check if an edge exists using an adjacency list?

You must scan the list for the vertex, which takes time proportional to the degree of the vertex.

Answer: O(degree)

Revision Sheet

EVERYTHING ON ONE SCREEN — LAST-MINUTE PASS
Recursion

Master theorem cases: T(n) = aT(n/b) + f(n). Stack space complexity is O(depth).

Arrays

O(1) access. Row-major: A[i][j] = Base + w*(i*cols + j). Column-major: A[i][j] = Base + w*(j*rows + i).

Linked Lists

O(n) search/access, O(1) insert/delete given pointer. Floyd's cycle detection: slow/fast pointers meet if cycle exists.

Stacks

LIFO structure. Useful for parsing, balanced parentheses. Cₙ = C(2n,n)/(n+1) counts, among other things: BSTs on n distinct keys, valid parenthesis sequences of length 2n, and stack-sortable permutations of n elements.

Queues

FIFO structure. Circular queue, one-empty-slot convention: full when (rear + 1) % N == front, empty when front == rear. (A size-counter implementation instead uses count == N / count == 0, and can hold all N slots.)

Trees

Leaf nodes n₀ = degree-2 nodes n₂ + 1. Max nodes at height h (0-indexed): 2ʰ⁺¹ − 1. Traversals: In, Pre, Post.

BST & AVL

BST operations O(h). Inorder gives sorted order. Deletion: 0 children → delete; 1 child → replace by child; 2 children → successor/predecessor. AVL balance factor: h(L) − h(R) ∈ {−1, 0, 1}. Rotations restore balance.

Binary Heaps

Min-heap → minimum at root; extract-min is O(log n) in a min-heap. Max-heap → maximum at root; extract-max is O(log n) in a max-heap — don't invert which extreme goes with which heap. Bottom-up build-heap = O(n) — NOT n×O(log n) = O(n log n); that bound applies only to repeated single insertion. 0-indexed formulas: parent = ⌊(i−1)/2⌋, left = 2i+1, right = 2i+2. Heap sort O(n log n).

Graphs

Handshaking lemma: ∑ deg = 2|E|. BFS (Queue, shortest path in unweighted graph only; connected components in an undirected graph). DFS (Stack; cycle detection — undirected: visited neighbor ≠ parent, directed: back edge to a recursion-stack node). Weighted shortest path: Dijkstra (non-negative weights) / Bellman-Ford (negative weights allowed). Tree has V−1 edges.

Complexities

Hash tables expected O(1) search/insert. Sorting: Merge/Heap O(n log n), Quick expected O(n log n), worst O(n²).

BST deletion — the 3 cases, canonical form
0 children (leaf) → delete the node directly 1 child → replace the node with that single child 2 children → replace with inorder successor (or predecessor), then delete THAT node from its new position (which now has at most 1 child — reduces to a case above)

In-order successor = minimum of the right subtree (go right once, then left as far as possible). In-order predecessor = maximum of the left subtree (go left once, then right as far as possible). Either choice yields a valid BST — GATE sometimes asks which one a trace used, not which is "more correct."

Why build-heap is O(n), not O(n log n)

Wrong intuition: "n insertions × O(log n) each = O(n log n)." That reasoning only applies to building a heap via repeated single insertion.

Bottom-up build-heap (heapify-down from the last non-leaf node up to the root) is O(n) instead, because most nodes sit near the leaves and have very little sift-down work to do — only a handful of nodes near the root pay the full O(log n) cost.

repeated insert → O(n log n) bottom-up build-heap → O(n)

Practice — rapid-fire mix (original)

6 questions
Q1 Assuming all keys are distinct, what is the pre-order traversal of a BST if the post-order is 2, 4, 3, 7, 9, 8, 5?

Root is last in post-order: 5. BST property splits into left {2,4,3} and right {7,9,8}. Reconstructing yields pre-order: 5, 3, 2, 4, 8, 7, 9. (This reconstruction relies on all keys being distinct — with duplicate keys, whether equal values go left or right depends on the implementation's convention, and reconstruction from a single traversal can become ambiguous.)

Answer: 5, 3, 2, 4, 8, 7, 9 (assumes distinct keys)

Q2 In an adjacency list representation of a directed graph, how do you find the in-degree of all vertices?

You must traverse all lists of all vertices. The in-degree of vertex V is the number of times V appears in all adjacency lists combined, taking O(V+E) time overall.

Answer: Scan all adjacency lists, counting occurrences

Q3 What is the relationship between the number of leaves (L) and internal nodes with 2 children (I) in a strictly binary tree?

In any binary tree, the number of leaf nodes n₀ is exactly one more than the number of nodes with two children n₂. Thus, L = I + 1.

Answer: L = I + 1

Q4 A circular queue of size N=5 (using the one-empty-slot convention) has front=2 and rear=1. Is the queue full or empty?

Under the one-empty-slot convention (no separate count variable, one slot deliberately left unused to disambiguate full from empty), the condition for full is (rear + 1) % N == front. (1 + 1) % 5 = 2, which equals front. So the queue is full. (This formula is specific to that convention — an implementation using a size counter instead would check count == N, with no such sacrificed slot.)

Answer: Full (under the one-empty-slot convention)

Q5 A min-heap of n elements is given, with no other information about how it was built. What is the worst-case time to find the median if we inspect all heap elements and use a linear-time selection algorithm (e.g. median-of-medians)?

A min-heap only guarantees the root is the smallest — it maintains no order among the rest of the elements, so there's no way to locate the median faster than looking at all n elements. Once all n values are available (e.g. by an O(n) traversal of the underlying array), a linear-time selection algorithm finds the median (the n/2-th order statistic) in O(n) worst-case time, without needing to fully sort.

Answer: O(n) — O(n) to read all elements + O(n) for linear-time selection

Q5b Same min-heap of n elements — but this time, find the median by repeatedly extracting the minimum until reaching the middle element. What is the time complexity now?

Each extract-min on a heap of current size k costs O(log k). To reach the median you must extract roughly n/2 elements, and each of those extractions costs up to O(log n), so the total cost is the sum of n/2 individual O(log n) operations.

Answer: O(n log n) — this method is correct but asymptotically worse than the O(n) selection approach in Q5
