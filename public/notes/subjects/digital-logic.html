Number Systems & Codes

RADIX CONVERSION · COMPLEMENTS · BCD · GRAY CODE

Positional number systems

Any number in base r with digits d represents a value as a weighted sum of powers of r:

N = Σ dᵢ · ri (i runs over each digit position, powers of r increase left to right of the point)

Common bases

BaseRadixDigits
Binary20, 1
Octal80–7
Decimal100–9
Hex160–9, A–F
Fast conversion trick

Octal ↔ binary: group bits in 3s. Hex ↔ binary: group bits in 4s. Always group starting from the binary point outward — pad with zeros at the far ends only.

Complements — the key to subtraction by addition

For any base r, two complements matter: the (r−1)'s complement and the r's complement.

Binary (r = 2)

1's complement: flip every bit.
2's complement: 1's complement + 1. Equivalently — copy bits up to and including the first 1 (from LSB), flip the rest.

General radix

(r−1)'s complement of N (n digits) = (rn − 1) − N.
r's complement = (rn) − N = (r−1)'s complement + 1.

2's complement is used almost universally to represent signed integers because it gives a single representation for zero and lets addition/subtraction use the same adder hardware (see Section 09).

Binary codes

BCD (8421 code)

Each decimal digit (0–9) coded in 4 bits using its natural binary value. Wastes 6 combinations (1010–1111) per digit — invalid states GATE loves to ask about.

Excess-3 code

Add 3 (0011) to the 4-bit binary of each decimal digit. Self-complementing: 9's complement of a digit = bitwise complement of its Excess-3 code.

Gray code (reflected binary)

Adjacent values differ in exactly one bit — used in K-maps and rotary encoders to avoid glitches when multiple bits change at once.

Binary → Gray: g₀ = b₀ (MSB same); gᵢ = bᵢ ⊕ bᵢ₋₁ for i > 0 Gray → Binary: b₀ = g₀; bᵢ = bᵢ₋₁ ⊕ gᵢ for i > 0

Number of 1's differing between two consecutive Gray codes is always exactly 1 — but the number of bit positions that differ between binary equivalents of Gray-adjacent values is not constant. Don't confuse "Gray distance" with "Hamming distance of the binary form."

Practice — GATE style (original)

5 questions
Q1 Find the 8-bit 2's complement representation of −45.

45 in binary (8-bit) = 00101101. Invert all bits (1's complement): 11010010. Add 1: 11010011.

Answer: 11010011

Q2 Convert (247)₁₀ to octal.

Divide repeatedly by 8: 247 ÷ 8 = 30 r 7; 30 ÷ 8 = 3 r 6; 3 ÷ 8 = 0 r 3. Read remainders bottom-up: 3, 6, 7.

Answer: (367)₈

Q3 Find the Gray code equivalent of binary 1011.

Working left to right by position (no subscript convention needed): the Gray code's leftmost (MSB) bit equals the binary's leftmost bit. Each subsequent Gray bit is the XOR of the binary bit at that position with the binary bit immediately to its left. Binary: 1 0 1 1. Gray bit 1 (leftmost) = 1 (same as binary). Gray bit 2 = 1⊕0 = 1. Gray bit 3 = 0⊕1 = 1. Gray bit 4 (rightmost) = 1⊕1 = 0.

Answer: 1110

Q4 How many 4-bit patterns are wasted (invalid) per digit in standard 8421 BCD, and which values are they?

4 bits give 16 combinations (0000–1111), but BCD only uses 0000–1001 (0–9) for a single digit. That leaves 1010–1111 unused.

Answer: 6 combinations wasted (values 10–15 in binary)

Q5 Find the Excess-3 code of decimal 6, and verify the self-complementing property against decimal 3.

Excess-3(6) = binary(6) + 0011 = 0110 + 0011 = 1001. Excess-3(3) = 0011 + 0011 = 0110. Note 6 and 3 are 9's complements of each other (6+3=9), and their Excess-3 codes 1001 and 0110 are bitwise complements of each other — confirming the self-complementing property.

Answer: Excess-3(6) = 1001

Boolean Algebra & Logic Gates

LAWS · DUALITY · UNIVERSAL GATES · CANONICAL FORMS

The seven laws

LawOR formAND form
IdentityA + 0 = AA · 1 = A
NullA + 1 = 1A · 0 = 0
IdempotentA + A = AA · A = A
ComplementA + A' = 1A · A' = 0
CommutativeA + B = B + AAB = BA
DistributiveA+(BC) = (A+B)(A+C)A(B+C) = AB+AC
AbsorptionA + AB = AA(A+B) = A
De Morgan's theorem
(A + B)' = A'·B' (A · B)' = A' + B'

Extends to n variables. This is the theorem behind converting any circuit to all-NAND or all-NOR form.

Duality principle

Swap every + ↔ · and every 0 ↔ 1 in a true Boolean identity and it stays true. Useful to derive one law's form from the other instantly instead of memorizing both.

Logic gate symbols & truth tables

ANDY = A·B
ORY = A+B
NOTY = A'
NANDY = (AB)'
NORY = (A+B)'
XORY = A⊕B
Universal gates

NAND and NOR are each functionally complete — any Boolean function can be built using only one of them. Tying both inputs of a NAND together gives NOT; two NANDs in series with the right wiring give AND, OR, etc. This is exactly why real chips (7400 series) are built from NAND/NOR gates.

Canonical forms

SOP — Sum of Products

OR of minterms. A minterm is a product term where every variable appears exactly once (true or complemented) — it is 1 for exactly one input row.

F(A,B,C) = Σm(1,3,5,6) = A'B'C + A'BC + AB'C + ABC'

POS — Product of Sums

AND of maxterms. A maxterm is a sum term where every variable appears exactly once — it is 0 for exactly one input row.

F(A,B,C) = ΠM(0,2,4,7)
GATE trap

SOP is naturally formed from the minterms where F=1 (the rows the function is true for); POS is naturally formed from the maxterms where F=0 (the rows the function is false for). Minterm index i and maxterm index i are complementary rows of the same truth table: if a function's minterm list is {1,3,5,6}, its maxterm list is everything else — {0,2,4,7}. So for the same function, F = Σm(1,3,5,6) = ΠM(0,2,4,7) — the same F, expressed two ways, using complementary index sets over the full range of rows. GATE frequently asks you to convert Σm ↔ ΠM directly without redrawing the truth table; the most common mistake is listing the same index set for both instead of complementing it.

Practice — GATE style (original)

5 questions
Q1 Simplify F = A + A'B using Boolean algebra.

A + A'B = (A + A')(A + B) [distributive] = 1·(A+B) = A + B.

Answer: F = A + B

Q2 Express F = AB + C'D using only NOR gates (apply De Morgan).

F = AB + C'D. Double-complement: F = ((AB + C'D)')' = ((AB)'·(C'D)')'. Mechanically, replace every AND with De Morgan's OR-of-complements form and implement every OR/complement stage with NOR (written X↓Y = (X+Y)'). Concretely, using NOR with tied inputs for NOT:

  • A' = A↓A, B' = B↓B
  • AB = A'↓B' (since (A'+B')' = A·B by De Morgan)
  • C' = C↓C, D' = D↓D
  • C'D = C↓D' (since (C+D')' = C'·D by De Morgan)
  • F = (AB↓C'D)↓(AB↓C'D) (the standard double-NOR construction for OR: NOR(X,Y) fed into itself gives X+Y)

So F = (AB↓C'D)↓(AB↓C'D). Counting each NOR used in the construction above: A' (1), B' (1), AB (1), C' (1), D' (1), C'D (1), plus the final double-NOR OR stage which itself takes 2 NOR gates (one to compute AB↓C'D, one more to feed that result into itself to recover the OR) — 6 + 2 = 8 two-input NOR gates total. (This is the gate count for the specific construction shown, not a claim that 8 is the global minimum for a NOR-only implementation of this function.)

Key idea: repeatedly apply (X)'' = X and De Morgan until every operator is expressible as NOR — see the gate-by-gate construction above for F = (AB↓C'D)↓(AB↓C'D); this construction uses 8 two-input NOR gates

Q3 F(A,B,C,D) = ΠM(0,2,4,6,8,10,12,14). Write F in Σm form.

Maxterm list and minterm list are complementary over 0–15. The given maxterms are exactly all even indices, so the minterms are all odd indices: 1,3,5,7,9,11,13,15.

Answer: F = Σm(1,3,5,7,9,11,13,15) — this is simply F = D

Q4 Minimum number of 2-input NAND gates needed to implement XOR (A⊕B)?

A⊕B = AB' + A'B. Using only NAND: NAND1 = (AB)', then feed A and NAND1 into NAND2, B and NAND1 into NAND3, finally NAND4 combines NAND2 and NAND3's outputs. This is the standard 4-NAND XOR construction.

Answer: 4 NAND gates

Q5 How many distinct Boolean functions are possible with 3 input variables?

A truth table for n variables has 2ⁿ rows; each row's output can independently be 0 or 1, giving 2^(2ⁿ) distinct functions. For n=3: 2³ = 8 rows, so 2⁸ = 256 functions.

Answer: 256

K-Map & Quine–McCluskey

GROUPING RULES · PRIME IMPLICANTS · DON'T-CARES

Karnaugh map — grouping rules

The 7-point checklist — wrap-around, overlap, and don't-cares included
  • Groups must contain exactly 1, 2, 4, 8, 16, ... cells (a power of 2) — never 3, 5, 6, etc.
  • Rectangular groups only — a valid group is always a rectangle (a single cell, a 1×2/2×1 pair, a 2×2 or 1×4 block, and so on); diagonal or L-shaped "groups" are never valid.
  • The map wraps around on both axes — leftmost and rightmost columns are adjacent, and top and bottom rows are adjacent (the map is topologically a torus).
  • Overlapping groups are allowed — the same cell can belong to more than one group if that helps cover things more efficiently.
  • Don't-care cells (X) may be used to help form a bigger group, but a group can never consist purely of don't-cares.
  • Make every group as large as possible — a bigger group (more cells) always eliminates more literals and gives a simpler term.
  • Every required 1 must be covered by at least one group in the final solution — an uncovered 1 means the minimization is incomplete (wrong).

A group of 2ᵏ cells eliminates k variables from the resulting term — the variables that change across the group drop out; variables that stay constant remain.

Reading a group

For any group, write only the variables that are constant across every cell in it (uncomplemented if the variable = 1 throughout, complemented if = 0 throughout); AND them together. A single cell keeps all n variables; the full map (all 2ⁿ cells) reduces to constant 1.

Quine–McCluskey (tabular method)

Used when there are too many variables to map visually, or the process needs to be algorithmic (as it is inside a compiler/EDA tool).

  1. Group minterms by number of 1's in their binary form.
  2. Combine pairs of minterms from adjacent groups that differ in exactly one bit; replace that bit with a dash (–). Tick off every minterm that gets combined.
  3. Repeat combining on the new table (dashes must align) until no further combination is possible.
  4. Terms that never got ticked off (in any pass) are prime implicants (PIs).
  5. Build a PI chart: rows = PIs, columns = minterms. A column with a single ✕ marks an essential PI — it must be in the final answer.
  6. Select essential PIs first, then cover any remaining minterms with the fewest additional PIs (Petrick's method for the general case).
GATE trap

Number of prime implicants and number of essential prime implicants are not the same thing, and GATE frequently asks for one or the other precisely. A function can have PIs that are never essential — they cover only minterms already covered by other essential PIs, so a minimum SOP may exclude them entirely.

Don't-care conditions

Arise when certain input combinations physically cannot occur (e.g. invalid BCD codes 1010–1111) or their output value is irrelevant to the design. Marked X or d in the map/table — treat as 1 or 0, whichever minimizes the expression further.

Static hazards — the K-map trap that's easy to miss

A hazard is a momentary, unwanted glitch in a combinational circuit's output caused by different propagation delays along different paths, when more than one input literal changes for a given transition. Two flavors matter most for GATE:

Static-1 hazard

The output is supposed to stay at 1 across the transition, but it can briefly glitch down to 0 before settling back at 1.

Static-0 hazard

The output is supposed to stay at 0 across the transition, but it can briefly glitch up to 1 before settling back at 0.

GATE trap — spotting and fixing a static-1 hazard on the K-map

A static-1 hazard shows up on a K-map exactly where two adjacent 1-cells are covered by two DIFFERENT groups, with no single group covering both — the transition between those two cells crosses a "seam" between product terms, and if one term is turning off exactly as the other is turning on, a brief dip to 0 can occur if the off-path is faster than the on-path.

Fix: add a redundant (consensus) implicant that covers that exact adjacent pair — a group that is not needed for the minimum SOP's logical coverage (both cells are already covered by other groups individually) but overlaps the seam between them, so at least one term stays 1 throughout the transition and the output never has a reason to dip. This redundant group typically corresponds to the "consensus term" of the two overlapping groups' terms. The cost is a slightly less minimal circuit (one extra gate/term) in exchange for glitch-free behavior across that transition — a classic minimality-vs-hazard-freedom trade-off GATE likes to test conceptually.

Static-0 hazards are handled the mirror-image way, using a POS (product-of-sums) K-map covering the 0-cells and adding a redundant sum term across the seam between two adjacent 0-groups.

5 questions
Q1 Minimize F(A,B,C) = Σm(0,1,2,5,6,7) using a K-map.

Plotting the 3-var map: group {0,1,4,5}? — check the actual 1-cells: 0(000),1(001),2(010),5(101),6(110),7(111). Group {6,7,2,3}? 3 isn't a minterm here, so use {2,6} (BC'=... let's group directly: {0,1} → A'B'; {6,7} → AB; {2,6} → BC'... combining carefully gives F = A'B' + BC' + AC, verified by rechecking each minterm is covered.

Answer: F = A'B' + AC + BC' (each minterm 0,1,2,5,6,7 covered — verify by substitution)

Q2 F(A,B,C,D) = Σm(0,2,5,7,8,10,13,15). Find the minimized SOP.

Notice every minterm has B⊕D = 0 pattern... checking: this classic "checkerboard" function is the XNOR of two variable-pairs. Working it out on the K-map, the 1-cells do combine into two 4-cell groups: {0,2,8,10} all have B=0,D=0, giving B'D'; and {5,7,13,15} all have B=1,D=1, giving BD. (Individually the minterms look scattered/checkerboard-like across the map, but B and D — not A and C — are the constant variables tying each group together.)

Answer: F = B'D' + BD (equivalently F = (B⊕D)'), and no further simplification is possible — a good example of a function needing every prime implicant

Q3 Using Quine–McCluskey, combine minterms m5 (0101) and m7 (0111).

Compare bit by bit: 0101 vs 0111 — they differ only in the 3rd bit (from left, 0-indexed position 2). Since exactly one bit differs, they combine, replacing that bit with a dash.

Answer: 01-1 (both minterms get ticked off as combined)

Q4 F(A,B,C,D) = Σm(1,3,7,11,15). How many essential prime implicants does it have?

All listed minterms have D=1. Plotting on the K-map: 1(0001), 3(0011), 7(0111), 11(1011), 15(1111) — all lie in the D=1 half. Grouping: {1,3} combine to A'B'D (a group of 2, since no adjacent minterm 5 or 9 is present to grow it further), and {3,7,11,15} form a group of 4 giving CD (C and D constant = 1 across all four). A prime implicant is essential specifically when it is the only prime implicant covering some minterm — not because of its group size. Checking each minterm: m1 is covered only by A'B'D (no other PI reaches it) — so A'B'D is essential. m11 (and m15) are covered only by CD (no other PI reaches them) — so CD is essential. m3 happens to be covered by both A'B'D and CD, so m3 alone wouldn't make either one essential, but each is already essential on the strength of m1 and m11 respectively.

Answer: 2 essential prime implicants — A'B'D (essential via m1) and CD (essential via m11/m15)

Q5 Minimize F(A,B,C) = Σm(1,3,5) + d(0,2,4) using don't-cares.

Minterms 1,3,5 must be 1; 0,2,4 are don't-care; 6,7 are 0 by omission. On the K-map, setting don't-cares 0,2,4 to 1 lets two 4-cell groups form: A=0 covers {0,1,2,3} (all 1 or don't-care) giving term A', and B=0 covers {0,1,4,5} (all 1 or don't-care) giving term B'. Together A'+B' cover 1,3,5 exactly, while m6(110) and m7(111) — both A=1,B=1 — are correctly left at 0 since neither group reaches them. (Setting F=C would wrongly force F(7)=1, but m7 is a hard 0, not a don't-care — so F=C is not a valid minimization here.)

Answer: F = A' + B'

Adders & Subtractors

HALF/FULL ADDER · RIPPLE CARRY · CARRY LOOK-AHEAD

Half adder

Adds two single bits, no carry-in.

ABSC
0000
0110
1010
1101
S = A⊕B C = A·B

Full adder

Adds A, B and a carry-in Cin. Built from two half adders + OR gate.

S = A ⊕ B ⊕ Cin Cout = AB + Cin(A⊕B) = AB + BCin + ACin

Cout is 1 whenever at least two of A, B, Cin are 1 — it's a majority function.

4-bit ripple carry adder — Cout of each stage feeds Cin of the next.
Ripple carry vs carry look-ahead

Ripple carry adder (RCA): n full adders chained; simple, but worst-case delay grows O(n) since carry must propagate through every stage. Carry look-ahead adder (CLA): computes each carry directly from the inputs using generate/propagate signals, cutting delay to roughly O(log n) at the cost of more hardware.

Gᵢ = Aᵢ·Bᵢ (generate) Pᵢ = Aᵢ⊕Bᵢ (propagate) Cᵢ₊₁ = Gᵢ + Pᵢ·Cᵢ

Subtractor via 2's complement

A − B is computed as A + (2's complement of B), using the same adder hardware as addition:

A − B = A + B' + 1 → feed B through XOR gates with a mode signal M M = 0 : Adder (XOR passes B unchanged, Cin = 0) M = 1 : Subtractor (XOR inverts B, Cin = 1)

A discarded/ignored final carry-out in this scheme signals the result's sign convention in 2's complement arithmetic — see Section 09 for overflow detection rules.

GATE trap — ripple-carry delay has no single universal formula

There isn't one formula that always applies — always use the delay model given in the question. Different problems define the per-stage delay differently: carry-propagation delay (tcarry, the time for Cin→Cout through one full adder) is often NOT the same as sum delay (tsum, the time for inputs→S through one full adder), and some problems only give a single generic "gate delay" meant to stand in for both. Read exactly which delay(s) are defined before plugging into any formula.

If the question gives you both delays separately (the common, safer case), for an n-bit ripple carry adder:

Final carry-out (Cₙ) ≈ n × t_carry (Cₙ must ripple through all n stages' carry chains) Final sum (Sₙ₋₁, the most-significant sum bit) ≈ (n−1) × t_carry + t_sum (the carry ripples through the first n−1 stages, then the last stage additionally needs its own sum-gate delay)

If tcarry = tsum = t (a single flat delay per full adder, as some simplified problems assume), this collapses to Cₙ ≈ n·t and the final sum ≈ (n−1)·t + t = n·t — which is where the older "n·t + one extra sum-gate delay" shorthand came from. Treat that shorthand as a special case of the general model above, not the default — check the problem's stated delays before assuming carry and sum delays are equal.

Practice — GATE style (original)

5 questions
Q1 A full adder has inputs A=1, B=0, Cin=1. Find S and Cout.

S = A⊕B⊕Cin = 1⊕0⊕1 = 0. Cout = AB + BCin + ACin = (1·0)+(0·1)+(1·1) = 0+0+1 = 1.

Answer: S = 0, Cout = 1

Q2 Each full adder in a 4-bit ripple carry adder has a carry delay of 2 gate-delays and a sum delay of 3 gate-delays. Find the worst-case time to produce the final sum output S₃.

The carry must ripple through the first 3 stages before reaching the 4th: 3 stages × 2 = 6 gate-delays. The 4th stage then needs its own sum delay of 3 gate-delays on top of that.

Answer: 6 + 3 = 9 gate-delays

Q3 Assuming only 2-input NAND gates are allowed and intermediate outputs may be freely reused, what is the minimum number of 2-input NAND gates needed to implement a half adder?

A half adder needs S = A⊕B and C = AB. Under these assumptions, a standard NAND-only build uses 5 two-input NAND gates total (the classic XOR-from-NAND network of 4 gates, reusing its intermediate signals, plus 1 more NAND, inverted, to derive AB).

Answer: 5 NAND gates

Q4 Compute A − B for A = 0101, B = 0011 (4-bit) using 2's complement addition.

2's complement of B=0011: invert → 1100, add 1 → 1101. Now add: 0101 + 1101 = 10010. Discard the carry-out beyond bit 3, leaving 0010.

Answer: 0010 (decimal 2, correct since 5 − 3 = 2)

Q5 In a carry look-ahead adder, G₀=0, P₀=1, G₁=1, P₁=0, and C₀=1. Find C₂.

C₁ = G₀ + P₀C₀ = 0 + (1·1) = 1. C₂ = G₁ + P₁C₁ = 1 + (0·1) = 1.

Answer: C₂ = 1

MUX, Decoders & Encoders

DATA SELECTORS · CODE CONVERTERS · IMPLEMENTING FUNCTIONS WITH MUX

Multiplexer (MUX)

A 2ⁿ:1 MUX selects one of 2ⁿ data inputs using n select lines and routes it to a single output.

Y = Σ (Dᵢ · mᵢ) where mᵢ is the i-th minterm of the select lines
Implementing an n-variable function with a MUX

A 2n−1:1 MUX can realize any n-variable Boolean function: put n−1 variables on the select lines, and on each data input place 0, 1, the remaining variable, or its complement — read straight off the truth table row-pairs.

GATE favorite

"Implement F(A,B,C) using a 4:1 MUX" — put A, B on select lines S1S0, then for each of the 4 combinations look at what C-value(s) make F = 1: the data input becomes 0, 1, C, or C' accordingly. This exact question type appears almost every year.

Demultiplexer (DEMUX)

The inverse of a MUX: one input routed to one of 2ⁿ outputs, chosen by n select lines. A decoder with an enable input is a demultiplexer.

Decoder

An n-to-2ⁿ decoder activates exactly one of 2ⁿ output lines based on the binary input code — each output line is literally one minterm.

Building larger decoders

A 3-to-8 decoder can be built from two 2-to-4 decoders (with enable) — the MSB of the 3-bit input drives the enable lines, cleanly splitting the 8 minterms into two groups of 4. This "decoder tree" idea generalizes to any size and is a recurring GATE construction question.

Encoder

The inverse of a decoder: 2ⁿ input lines (only one active at a time, ideally) compress to an n-bit binary code.

Priority encoder

Ordinary encoders break if more than one input is active simultaneously. A priority encoder resolves this by outputting the code of the highest-priority active input, ignoring lower-priority ones — and typically adds a "valid output" (V) signal that's 0 when no input is active at all.

Magnitude comparator

Compares two n-bit numbers A and B, producing three outputs: A>B, A=B, A<B.

A = B ⇔ every corresponding bit pair is equal (XNOR each pair, AND all results) For A > B: scan from MSB — the first bit position where they differ decides it (A's bit = 1, B's bit = 0)

Code converters

Any conversion between two n-bit codes (binary↔Gray, binary↔BCD, Excess-3↔BCD) is just a combinational circuit: write the truth table mapping input code to output code, then minimize each output bit independently with a K-map.

Programmable logic — ROM, PLA, PAL

All three implement Boolean functions as an AND array feeding an OR array, but differ in what's fixed vs programmable:

DeviceAND arrayOR array
ROMFixed (all minterms)Programmable
PLAProgrammableProgrammable
PALProgrammableFixed

A ROM used as logic realizes any n-input, m-output function directly since its AND array already generates every minterm — but it wastes AND gates for functions that don't need every minterm; a PLA/PAL only builds the product terms actually required, trading flexibility for smaller size.

Practice — GATE style (original)

5 questions
Q1 Implement F(A,B,C) = Σm(1,3,5,6) using a 4:1 MUX with A, B on the select lines. Find the four data inputs.

Fix A,B and see what value of C (or constant) makes F=1 for each pair, reading the minterm list against AB: AB=00 → row is m0=0,m1=1 → depends on C → input = C. AB=01 → m2=0,m3=1 → input = C. AB=10 → m4=0,m5=1 → input = C. AB=11 → m6=1,m7=0 → input = C'.

Answer: D0=C, D1=C, D2=C, D3=C'

Q2 How many 3-to-8 decoders (with enable) are needed to build a 5-to-32 decoder?

A 5-to-32 decoder needs 32 output lines. Each 3-to-8 decoder gives 8 outputs, so 32/8 = 4 decoders are needed at the second level, plus one 2-to-4 decoder (using the top 2 address bits) to generate the 4 enable signals that pick which 3-to-8 decoder is active.

Answer: 4 (3-to-8) decoders + 1 (2-to-4) decoder = 5 decoders total

Q3 A 4-input priority encoder (D3 highest priority) has inputs D3D2D1D0 = 0110. Find the output code.

D3=0 so it's not the priority winner. D2=1 is the highest active input, so the encoder outputs the code for index 2 regardless of D1 or D0's state.

Answer: Output = 10 (binary for 2), Valid(V) = 1

Q4 How many 3-input AND gates does a standard 3-to-8 decoder need (excluding any enable logic)?

Each of the 8 outputs is one distinct minterm of the 3 inputs, and each minterm needs its own 3-input AND gate.

Answer: 8 AND gates

Q5 Realize F(A,B,C) = A⊕B⊕C using an 8:1 MUX with A, B, C on the select lines.

With all 3 variables on select lines, each data input is simply the truth-table value for that row — no variables left to place on data lines. F is 1 for odd parity: rows 001,010,100,111 → minterms 1,2,4,7.

Answer: D1=D2=D4=D7=1, all other data inputs = 0

Latch vs flip-flop

A latch is level-triggered — transparent and follows its input whenever enable is asserted. A flip-flop is edge-triggered — it samples input only at a clock edge (rising or falling) and holds state otherwise. Flip-flops are what synchronous sequential circuits are built from.

Flip-flop conversion questions (e.g. "implement a D flip-flop using JK") are solved by comparing characteristic equations, not by memorizing a wiring diagram: write the target's characteristic equation, express J and K as functions of D and Q using the JK excitation table, then simplify. Positive edge-triggered D flip-flop — Q updates to D's value only at the rising edge of CLK, then holds.

Master–slave configuration

Two latches in series (master transparent while clock is high, slave transparent while clock is low, or vice versa) — this blocks race-around, the problem where a level-triggered JK latch with J=K=1 would toggle repeatedly for as long as the clock pulse stays active. Master-slave / true edge-triggered designs sample input only once per clock cycle.

Setup & hold time

Setup time (tsu): minimum time input must be stable before the clock edge. Hold time (th): minimum time input must remain stable after the clock edge. Violating setup/hold requirements can cause metastability and makes the sampled value unreliable — it doesn't guarantee metastability on every single occurrence, since the flip-flop's internal amplifier may still resolve to a valid 0 or 1 quickly enough most of the time, just with no guarantee of which value or how long resolution takes. Maximum clock frequency of a flip-flop chain is bounded by 1 / (tclk-to-q + tcombinational + tsu).

Why this is fundamentally probabilistic, not a binary trigger

Setup/hold violations are analog timing phenomena at heart — the flip-flop's internal latch is a bistable analog circuit, and a violation means the input changed while that circuit was still in the middle of resolving toward 0 or 1. Whether it resolves in time, resolves late, or hangs in an in-between voltage for an unbounded (theoretically unbounded) duration is a matter of physics and probability, not digital logic. The digital abstraction has no way to represent "resolving," so it simply treats the result as indeterminate/unreliable rather than claiming metastability is certain to occur.

5 questions
Q1 For a NOR-based, active-high SR latch, inputs S=1, R=1 are applied and then both are dropped to S=0, R=0 simultaneously. What happens?

This is specifically about the NOR-based active-high SR latch, where S=R=1 is the invalid combination. The interpretation flips for a NAND-based active-low SR latch (S=R=1 → hold, S=R=0 → invalid), so always check which implementation a question means before applying either analysis.

Two distinct things are happening here, and it's worth keeping them separate. First, S=R=1 is the forbidden/invalid input combination — it forces both Q and Q' toward 0, violating their required complementary relationship (Q and Q' are supposed to always be opposite). Second, when both inputs then drop to 0 at exactly the same instant from that invalid state, which output settles to 1 depends on tiny, unequal gate-propagation-delay mismatches between the two cross-coupled gates — this specific unpredictable settling is an indeterminate/unpredictable final state caused by propagation-delay mismatch. In practical implementations this race can also trigger genuine metastability (the output hovering at an invalid intermediate voltage before resolving), but "indeterminate final state" and "metastability" aren't strictly the same thing — don't equate every such race directly with metastability. This is also not the same phenomenon as "race-around" (which specifically refers to a level-triggered JK latch with J=K=1 toggling repeatedly for as long as its enable/clock pulse stays high — see the JK section). Don't use "race-around" for this SR case; reserve that term for the JK toggling issue.

Answer: Next state is indeterminate — an unpredictable settling outcome caused by unequal propagation delays (which can also trigger metastability in practice), distinct from JK's "race-around"

Q2 Derive the J and K inputs needed to make a JK flip-flop behave as a D flip-flop.

Target: Q(next) = D. JK characteristic equation: Q(next) = JQ' + K'Q. Matching term-by-term against D = D·Q' + D·Q (expanding D using Q,Q'): the Q' coefficient gives J = D, and the Q coefficient gives K' = D, so K = D'.

Answer: J = D, K = D'

Q3 A T flip-flop starts at Q=0 with T=1 held constant. What is Q after 5 clock pulses?

With T=1, the flip-flop toggles every clock pulse: 0→1→0→1→0→1 after pulses 1,2,3,4,5 respectively. After an odd number of toggles from 0, Q=1.

Answer: Q = 1

Q4 A D flip-flop has tclk-to-q = 2 ns, requires tsu = 1 ns, and drives 3 ns of combinational logic before the next flip-flop. Find the maximum clock frequency.

Minimum clock period Tmin = tclk-to-q + tcombinational + tsu = 2 + 3 + 1 = 6 ns. Maximum frequency = 1/Tmin.

Answer: fmax = 1/6ns ≈ 166.7 MHz

Q5 Why does a level-triggered JK latch (not master-slave) malfunction when J=K=1 and the clock/enable stays high for a long pulse?

With J=K=1 the latch is asked to toggle. But since it's level-triggered (transparent), it keeps re-sampling its own new output as long as enable stays high, and toggles repeatedly and uncontrollably for the pulse duration — a phenomenon called "race-around." The final state when the clock finally drops is unpredictable.

Answer: Race-around condition — fixed by using an edge-triggered / master-slave design instead

Counters & Registers

RIPPLE VS SYNCHRONOUS · MOD-N · RING/JOHNSON · SHIFT REGISTERS

Asynchronous (ripple) counters

Each flip-flop's clock input is driven by the previous flip-flop's output, not the master clock. Simple to build (usually T or JK flip-flops wired to toggle), but state changes ripple through stage by stage — delay grows with the number of bits, and the outputs are momentarily inconsistent (glitchy) during a transition.

Synchronous counters

Every flip-flop shares the same clock; next-state logic is computed combinationally from the present state. This avoids the cumulative ripple-clock delay that asynchronous counters have — but it does not mean glitch-free outputs. When multiple state bits change simultaneously, any combinational logic decoding those bits (e.g. an output decoder) can still produce transient glitches from unequal propagation delays across paths (a hazard), just like the Moore-output case discussed later on this page. Synchronous design needs more gate hardware than ripple counters; GATE's design questions almost always mean synchronous design. Outputs are glitch-free only if they're registered (latched synchronously) or the decode logic is otherwise hazard-controlled.

Synchronous counter design procedure
  1. Draw the state diagram / state table for the required count sequence.
  2. Choose flip-flop type; write the excitation table using its Q→Q' entries (Section 06).
  3. K-map each excitation input as a function of present-state bits.
  4. Draw the circuit from the minimized expressions.

Mod-N counters

A counter that cycles through N states before repeating. For N not a power of 2, an n-bit binary counter (2ⁿ ≥ N) needs extra reset/load logic to skip the unused states — e.g. a mod-6 counter using 3 flip-flops must force a reset when it reaches state 110 (6), jumping back to 000.

GATE trap

"Minimum number of flip-flops for a mod-N counter" = ⌈log₂N⌉ — always round up, and remember unused states (2ⁿ − N of them) can become don't-cares in the excitation K-maps, often simplifying the design significantly, unless the question demands self-correcting behavior from invalid states.

Ring counter

n flip-flops in a shift-register loop with a single 1 (or 0) circulating. Only n valid states out of 2ⁿ possible — wasteful of states but decoder-free (each flip-flop output directly indicates one count).

Johnson (twisted-ring) counter

Like a ring counter but the complemented output of the last stage feeds back to the first. Produces 2n valid states from n flip-flops — double the states of a ring counter for the same hardware.

GATE trap — a ring counter needs a valid one-hot start, or it locks up

The n valid states of a basic ring counter are the n one-hot patterns (exactly one flip-flop is 1, the rest are 0). This only works if the counter is initialized into one of those one-hot states — typically via a preset/clear pulse at startup, since flip-flops don't reliably power up into any particular known state on their own.

Crucially, the all-zero state (0000...0) is NOT one of the n valid states, and is a lock-up state for the basic ring counter: once every flip-flop is 0, shifting a 0 into a 0 keeps producing 0 forever — there's no 1 anywhere in the loop to circulate, so the counter can never recover into a valid one-hot pattern on its own. Any of the 2ⁿ − n other non-one-hot states (including all-zero, and any pattern with more than one 1) are similarly invalid — a basic ring counter has no self-correcting mechanism to return to a valid state once it strays into one of these, unlike counters designed with explicit unused-state handling.

Johnson counters have their own separate, complete cycle of 2n valid states (not n) — don't apply the ring counter's n-state / all-zero-is-invalid reasoning directly to a Johnson counter without adjusting for its doubled, differently-structured state cycle.

Shift registers

A chain of flip-flops (usually D-type) sharing a clock, where each stage's output feeds the next stage's input — data shifts one position per clock pulse.

Both are simply a shift register (usually SIPO or PIPO style) with its serial output wired back into its serial input — direct feedback for a ring counter, complemented feedback for a Johnson counter.

Q1 How many flip-flops are needed for a mod-6 counter, and how many unused states result?

Q2 A 4-bit asynchronous (ripple) counter uses flip-flops with 20 ns propagation delay each. Find the worst-case time for the counter to settle after a clock edge.

In a ripple counter each flip-flop's clock comes from the previous stage's output, so delays add stage by stage: 4 stages × 20 ns.

Answer: 80 ns

Q3 How many valid states does a Johnson counter built with 4 flip-flops have?

A Johnson (twisted-ring) counter with n flip-flops produces 2n valid states.

Answer: 2 × 4 = 8 states

Q4 A ring counter is built with 5 flip-flops. How many valid states does it have, and how many output decoding gates are needed to identify each state?

A ring counter with n flip-flops has exactly n valid states (one flip-flop is 1, rest are 0, circulating). Since each flip-flop's output directly corresponds to one unique count, no separate decoding gates are needed at all.

Answer: 5 valid states, 0 decoding gates needed

Q5 An 8-bit PISO (parallel-in serial-out) shift register is parallel-loaded in 1 clock cycle, and the first loaded bit is immediately visible at the serial output before any shift occurs. How many additional clock cycles are needed to shift all 8 bits out serially?

Since the first bit is already sitting at the serial output pin right after the load cycle (no shift needed to read it), each subsequent clock pulse shifts the next bit into position. Getting the remaining 7 bits out therefore takes exactly 7 more pulses.

This is why the question must state the output-sampling assumption explicitly: if instead the convention is that the output is sampled only on a clock edge (i.e. even the first bit requires a shift pulse to appear at the output), the answer becomes 8 additional cycles. Always pin down which convention applies before answering — don't assume one silently.

Answer: 7 additional clock cycles (8 total including the load), given the stated assumption that the first bit is visible immediately after loading

Finite State Machines

MEALY VS MOORE · STATE MINIMIZATION · STATE ASSIGNMENT

Moore machine

Output depends only on the present state. Output is written inside the state circle in the state diagram. Since output depends only on state (which is held in flip-flops and changes only at clock edges), it does not respond directly to asynchronous mid-cycle input changes — this makes Moore outputs generally less sensitive to input glitches than Mealy outputs, but usually needs more states for the same job.

Mealy machine

Output depends on present state AND current input. Output is written on the transition arrow. Can react within the same clock cycle (faster response) and often needs fewer states — but output can glitch if input changes mid-cycle.

GATE trap — "Moore is glitch-free" is an overstatement

Converting Mealy → Moore may require adding states (never removing), because a Moore state's output must be single-valued while the same Mealy state could produce different outputs depending on the incoming edge. Converting Moore → Mealy never needs extra states.

Don't repeat "Moore output is glitch-free" as an unqualified fact. A Moore output is decoded combinationally from the state bits — and combinational logic can glitch on its own, from propagation-delay skew when multiple state bits change simultaneously (a hazard), independent of any input glitch. What's actually true is narrower: Moore output doesn't react directly to asynchronous input changes, because it only depends on state, which updates synchronously. If the output itself is registered (latched into a flip-flop, synchronously sampled) that's a separate, stronger guarantee — "depends only on state" and "is glitch-free" are not the same claim.

State minimization

Two states are equivalent if, for every input, they produce the same output and transition to equivalent next states. Minimization merges equivalent states to shrink the machine without changing its input-output behavior.

Partitioning method
  1. Start with one partition (0-equivalence): group states by their output alone.
  2. Refine: split a group if, for some input, its members go to different groups in the current partition.
  3. Repeat until the partition stops changing — each final group is one equivalent (merged) state.

State assignment

Once minimized states are known, each gets a unique binary code stored in flip-flops. The choice of coding (binary, Gray, one-hot) changes the resulting combinational logic size and speed even though the FSM's behavior is identical — a classic design trade-off, and a frequent conceptual GATE question rather than a compute-heavy one.

  • Binary/sequential coding — fewest flip-flops (⌈log₂(states)⌉), more complex next-state logic.
  • One-hot coding — one flip-flop per state, but next-state/output logic is often much simpler and faster.

5 questions
Q1 How many states are needed in a Mealy machine to detect the overlapping sequence "101" in a serial bit stream?

Track how much of the pattern has been matched so far: S0 (no match / start), S1 (matched "1"), S2 (matched "10"), and on the next 1 from S2 we output 1 and go back to S1 (since the trailing "1" could start a new overlapping match). That needs 3 states.

Answer: 3 states

Q2 A Mealy state A produces two different outputs depending on which input triggers its transition (e.g. output 0 on input 0, output 1 on input 1). Why may state splitting be necessary when converting such a machine to Moore?

In Moore, output must depend on state alone — a single value per state. If Mealy state A produces two different outputs (0 and 1) depending on the input, no single Moore state can replicate both behaviors; A must be split into two Moore states, one for each output value, so that each resulting state has a single well-defined output. The exact number of states in the final Moore machine depends on the full transition structure of the original Mealy machine, not on this splitting rule alone.

Answer: A Moore state can only emit one output value, so any Mealy state with input-dependent outputs must be split into multiple Moore states — one per distinct output value it produces

Q3 Two states S1 and S2 have identical outputs for every input, and on every input both transition to the same next state. Are they equivalent?

By the equivalence definition: same output for every input, and next states are themselves equivalent (here, identical) for every input — both conditions hold.

Answer: Yes, S1 and S2 are equivalent and can be merged into one state

Q4 An FSM has 6 states. Compare the number of flip-flops needed for binary encoding vs one-hot encoding.

Binary encoding needs ⌈log₂6⌉ flip-flops. One-hot needs exactly one flip-flop per state.

Answer: Binary = 3 flip-flops, One-hot = 6 flip-flops

Q5 Why is a Moore machine's output described as less sensitive to glitches than a Mealy machine's — and is it actually glitch-free?

A Moore output depends only on the current state, which is stored in flip-flops and changes only at clock edges — so it never responds directly to an asynchronous or mid-cycle input change the way a Mealy output can. A Mealy output depends directly on the current input, so it can momentarily glitch if the input changes before the next clock edge. That said, "glitch-free" overstates it: a Moore output is still typically decoded by combinational logic from the state bits, and that decoding logic can itself glitch (a static/dynamic hazard) if multiple state bits change at once with different propagation delays — the state-only dependency removes one source of glitches (raw input), not all of them.

Answer: Moore output can't react to asynchronous input changes (state-only dependency), making it less glitch-prone than Mealy — but it's not automatically glitch-free, since combinational decoding of the state bits can still hazard

2's complement is asymmetric: it can represent one extra negative number (−2ⁿ⁻¹) that has no positive counterpart. For n = 8, range is −128 to +127, not −127 to +127 — this exact off-by-one is a recurring GATE numeric question.

Overflow detection (2's complement addition)

Overflow occurs ⇔ Carry INTO the sign bit ≠ Carry OUT of the sign bit Equivalently: overflow happens only when adding two numbers of the SAME sign produces a result of the OPPOSITE sign.

Adding a positive and a negative number can never overflow in 2's complement.

Floating point addition is not associative due to rounding at each step — (a+b)+c can differ from a+(b+c) in finite precision. Conceptual questions on this, and on why floating-point equality comparisons are unreliable, show up regularly.

Multiplies two 2's complement numbers by scanning multiplier bit-pairs and choosing add/subtract/no-op based on the transition, exploiting runs of 1s to skip redundant additions.

Q1 What is the range of signed integers representable in 6-bit 2's complement?

n=6: range is −2ⁿ⁻¹ to +(2ⁿ⁻¹−1) = −2⁵ to +(2⁵−1) = −32 to +31.

Q2 Add the 4-bit 2's complement numbers 0111 and 0001. Is there overflow?

0111 (+7) + 0001 (+1) = 1000 in binary. Both operands are positive (same sign), but the result 1000 has sign bit 1, meaning it reads as negative (−8) — a sign flip from adding two positives is exactly the overflow condition.

Answer: Yes, overflow occurs (correct result +8 doesn't fit in 4-bit signed range which maxes at +7)

Q3 Decode the IEEE-754 single precision value with sign=0, exponent=10000001 (129), mantissa=01000000000000000000000.

Actual exponent = 129 − 127 = 2. Mantissa fraction = 0.01000...₂ = 0.25. Value = (−1)⁰ × 1.25 × 2² = 1.25 × 4.

Answer: 5.0

Q4 Using Booth's algorithm, what is the sign of the product when multiplying −3 (multiplicand) by +5 (multiplier)?

Booth's algorithm correctly handles signed 2's complement operands directly (that's its whole purpose), so the result naturally comes out as a properly signed product without needing separate sign-magnitude bookkeeping. −3 × 5 = −15, and Booth's trace (scanning multiplier bit-pairs of 0101, adding/subtracting the multiplicand 11101 (−3) at the appropriate shifted positions per the 00/01/10/11 rule) reproduces exactly this value.

Answer: −15 (negative), correctly obtained directly from 2's complement operands

Q5 Explain briefly why floating-point addition is not associative, with the idea behind a numeric example.

Each floating-point addition rounds its result to fit the available mantissa bits. Adding a very large number and a very small number first can lose the small number's precision entirely (it "disappears" into rounding), while adding two similarly-sized numbers first preserves more of that precision before the large number is added — so (a+b)+c and a+(b+c) can round differently and land on different final values.

Answer: Rounding at each intermediate step depends on operand order, so grouping changes the final result

5 questions
Q1 A function's SOP has 3 essential prime implicants covering all its minterms between them. Is any further minimization step required?

If the essential PIs alone already cover every minterm, no additional (non-essential) PIs are needed — the minimum SOP is exactly the sum of those essential PIs.

Answer: No, the 3 essential PIs already form the minimum SOP

Q2 How many select lines does a MUX need to implement any 5-variable Boolean function directly (one variable on the data lines)?

To implement an n-variable function with one variable left over for the data lines, the MUX needs n−1 select lines, i.e. a 2ⁿ⁻¹:1 MUX. For n=5: 2⁴ = 16:1 MUX with 4 select lines.

Answer: 4 select lines (16:1 MUX)

Q3 A synchronous mod-10 (decade) counter uses how many flip-flops minimum, and how many of the unused states may be treated as don't-cares?

⌈log₂10⌉ = 4 flip-flops (2⁴=16 ≥ 10). Unused states = 16 − 10 = 6 — that count is fixed regardless of design choices. Whether those 6 states are actually usable as don't-cares in the excitation K-maps is a separate design decision, not automatic: treating them as don't-cares is only valid if the design doesn't need to specify what happens should the counter ever land in one of those states (e.g. on power-up or due to a glitch). If the design instead requires self-starting/self-correcting behavior — guaranteeing that any invalid state transitions back into the valid counting sequence within a bounded number of clocks — then the next-state behavior of some or all of those 6 states must be explicitly specified rather than left as "don't care," which can change (and typically increases) the minimized excitation equations.

Answer: 4 flip-flops; 6 unused states exist, and they may be used as don't-cares only if the design doesn't require self-starting/self-correcting behavior — otherwise their transitions must be defined

Q4 A JK flip-flop currently at Q=1 must go to Q(next)=1. What are the required J,K values from the excitation table?

From the JK excitation table, the transition 1→1 requires J=X (don't care) and K=0. With K=0, J=0 holds at 1 and J=1 sets/holds at 1 — either way Q stays 1, which is why J is don't-care. K must stay 0, since K=1 would reset (J=0) or toggle (J=1) Q to 0.

Answer: J = X, K = 0

Q5 An IEEE-754 single precision number has exponent field = 00000000 and a non-zero mantissa. What category does it fall into, and why is there no implicit leading 1?

An all-zero exponent field is reserved for subnormal numbers (also called denormalized/denormal numbers — older but still common terminology), or true zero if the mantissa is also zero. Subnormals exist to represent values smaller than the smallest normalized number, and they drop the implicit leading 1 (using 0.Mantissa instead of 1.Mantissa) specifically so the format can gracefully represent numbers approaching zero rather than jumping straight from the smallest normal value to zero.

Answer: Subnormal (denormalized) number; no implicit 1 because it extends range closer to zero than normalized encoding allows
